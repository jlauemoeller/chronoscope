## Findings
1. [nit] `src/app/layout.rs`, `toast_rect`: the `4` in `area.width.saturating_sub(4)` is a bare number. Change: name it, e.g. `TOAST_SCREEN_MARGIN: u16 = 4`, next to the other toast constants.
2. [nit] `src/components/help_line.rs`, `status_width` and `visible_hints`: these measure `STATUS_SEPARATOR.len()` and `HINT_SEPARATOR.len()` in bytes. The result is correct for today's ASCII separators. Change: use `.width()` (already imported), so the code stays correct if a separator ever contains non-ASCII characters.
3. [nit] The planner's placement rule (bottom border on row `h − 2`) has two side effects. At 80x24 the toast covers the overlay's bottom border (`…╰────╯╯` in `selector_with_toast_80x24_text`). At 120x40 it covers the end of the `ESC to Cancel` hint. The build notes say this follows the binding planner coordinates. No code change is needed for this task; it is flagged for the UI Reviewer and the planner to confirm.
4. [nit] `src/app/mod.rs`, `show_toast_for`: this reads `Instant::now()` directly, so the 2 s expiry cannot be tested through the `App` with an injected clock. The current tests use `Msg::ToastExpired` or zero and very long durations instead, which is enough. Optionally, pass a clock into the `App` later, when more toasts (copy/save/export) arrive.
5. [nit] The build notes list a test as `toast_edges_are_one_column_and_one_row_inside_the_screen`, but in code it is named `toast_edges_are_one_column_and_two_rows_inside_the_screen`. Change: correct the name in the build notes.
6. [nit] `src/components/toast.rs`, `box_style`: with a transparent theme the toast's bg is dropped and the box is `Clear`ed. This matches SPEC.md §4 line 198 (overlays use `Clear` instead of painting `surface` when the background is transparent) and matches `SelectorFrame`. However, it also drops a bg the user set explicitly with `[tokens] toast = { bg = "…" }`, because `parse.rs` accepts a toast bg. Change (optional): drop the bg only when it comes from the default `surface` role, not from an override, or document that transparent mode wins.
