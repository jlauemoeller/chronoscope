## Findings
1. [nit] `src/app/selector.rs`, `preselect_again` / `settle_preselection`: once every registered harness has reported, `preselecting` ends, whatever the data. One path then misses the `$PWD` match. The first `build` of a harness fails while its data dir exists. `src/index/worker.rs` `build`, `Err` branch: it sends an empty snapshot with `available = true`, and the only retry is a rebuild set off by a later filesystem event (not a timed retry, despite the "every few seconds" comment). When the real data arrives, `keep_selection` falls back to index 0, so the first project is selected instead of the working-directory match. Ordinary startup (one build per harness, no cached snapshot sent first) is correct and tested, and the spec does not say whether preselection runs again after the index recovers, so this is not a spec breach. Change, if wanted: keep a separate "user acted" flag (set in `selector_msg`) apart from `preselecting`. When a snapshot of the current harness arrives while no project is selected (`self.selector.project.is_none()`) and the user has not acted, apply `preselection()` instead of `keep_selection`'s index-0 fallback. That leaves the tested freeze (`a_late_snapshot_after_every_harness_reported_does_not_move_the_preselection`) untouched. Add an update test: an empty snapshot for Claude, then one that contains the matching project, and the preselection follows the match.
2. [nit] `src/app/selector.rs`, `harness_empty`: it is true when every session list is empty, not when there are no projects. A harness that listed projects with zero sessions would show them in Projects while Sessions says "No sessions for this harness". This cannot happen today, because Claude's `build_index` (`src/harness/claude/discovery.rs`) builds projects only from groups of sessions. A future adapter that lists projects separately (e.g. a database-backed one) could trigger it. Change: also require `data.projects.is_empty()`, or add a comment stating the invariant.
3. [nit] `src/app/runtime.rs`: when `current_dir()` fails, the fallback is `PathBuf::new()`. An empty path matches only a project whose cwd is also empty (`Path::new("").starts_with("")` is true), so in practice this always falls back correctly. Wrapping the working directory in an `Option` would make the "unknown" case explicit. Optional.
