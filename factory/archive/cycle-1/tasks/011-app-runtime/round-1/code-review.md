## Findings
1. [nit] `src/components/global_events.rs`, `GlobalEvents::subscriptions` / `quit_key_events`: `Ctrl-c`, `WindowResize` and `Tick` all sit behind `subscription_clause()`. That function's doc tells later tasks to change this one clause so global keys stop firing while a `Prompt` or overlay has focus. Following that advice would also silence `Ctrl-c`, which must always quit (SPEC §1.4, §6.5), and would also block resizes and ticks. Change: subscribe `Ctrl-c`, `WindowResize` and `Tick` with `SubClause::Always` directly, and use `subscription_clause()` only for the keymap-derived global keys. One option is to keep `CTRL_C` out of `quit_key_events` and add its `Sub` separately.
2. [nit] `src/app/redraw.rs`, `RedrawLimiter::should_draw`: the AC asks for two things that conflict. "Never two draws less than 50 ms apart" cannot hold if a resize is also drawn "immediately". The builder lets a resize bypass the interval, documents the exception and tests both behaviours. That is the plain reading, so it is accepted here. Side effect: while a window is being dragged, every loop iteration that collects a `WindowResize` draws at once, so draw frequency is bounded only by the resize event rate and not by 50 ms. That is fine for now. If it shows up as a cost later, consider coalescing resizes, e.g. at most one immediate draw per interval, with the rest drawn as `Dirty`.
3. [nit] `src/app/tests.rs`, `every_quit_key_ends_the_loop` and `other_keys_do_not_end_the_loop`: the `Script` port returns `None` forever, so if quitting breaks these tests hang instead of failing. Change: spawn a watchdog thread that sets the shutdown `AtomicBool` after about 2 s (pass an `Arc<AtomicBool>`), then keep the `assert!(app.should_quit())`, so a regression shows up as a failure.
4. [nit] `src/components/global_events.rs`, test `every_default_quit_key_quits`: it hardcodes `q`, `Ctrl-q` and `Ctrl-w`. To match "every default global `quit` key" even if the defaults change, iterate `Keymap::default().keys(Context::Global, Action::Quit)`, turn each sequence into an event, and assert `Msg::Quit`. Keep the explicit `Ctrl-c` case.
5. [nit] `src/app/runtime.rs`, `run_app`: logging is initialised before the config is loaded, the reverse of the planner's steps 1–2. Since `init_logging` depends only on `Paths`, this is equivalent or better, because config-load diagnostics can reach the log. No change needed; mention it in the build notes so the deviation is recorded.
6. [nit] `src/app/tests.rs`, `every_builtin_theme_draws_the_startup_frame`: SPEC §9.6 asks for screen snapshots "for each built-in theme at a fixed size". This task's binding snapshot convention limits it to `default` plus the transparent state, so this smoke test (it only checks for `╭`) is acceptable here. Per-theme `App::view` snapshots should be added once screens have content (e.g. with the theme selector task).
7. [nit] `src/terminal.rs`, `TerminalGuard::drop`: it calls `self.adapter.restore()` explicitly, but `CrosstermTerminalAdapter` already restores its tracked modes in its own `Drop`, and it installs its own panic hook in `new()`. The explicit call is harmless but redundant. Also, both panic hooks restore the terminal on a panic in *any* thread, so once worker threads exist, a worker panic would restore the terminal while the main loop keeps drawing. Consider having the hook also set the shutdown flag, or check `std::thread::current()`, when worker threads arrive.
