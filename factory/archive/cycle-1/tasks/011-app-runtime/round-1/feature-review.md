## Findings
1. [nit] The startup order differs from the planner note without saying so. The note's order is "1. loads config; 2. initialises logging". `src/app/runtime.rs` `run_app` initialises logging (from `Paths`) before `AppInit::load`, and the `AppInit::load` doc relies on that order so that config warnings reach the log. The result is arguably better, since no config key affects logging. Change: add this to the "Decisions to note" in the build notes, or swap the order if strict adherence is wanted.
2. [nit] `CrosstermTerminalAdapter::new()` (called in `TerminalGuard::enter`) installs tuirealm's own panic hook on top of the one from `install_panic_hook()`. So in production tuirealm's hook runs first and ours second. Both restore before the default message is printed, so the behaviour is correct, but the doc comment on `install_panic_hook` in `src/terminal.rs` suggests ours is the outermost hook. Change: add a sentence to that doc comment saying the adapter wraps it.
