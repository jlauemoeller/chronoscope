## Findings
1. [nit] `src/components/turn_block/sections/mod.rs:32-34`: `pub const TEXT_COLUMN` is never used anywhere (the widget and the tests hard-code the column). It is public, so the compiler does not warn about it, but it is dead code. Its doc comment ("The columns taken by … on the left of the text: border, padding, and the two marker cells") also repeats itself. Change: either use it, e.g. in `widget.rs` or in the column-4 tests, or remove it.
2. [nit] `src/components/turn_block/mod.rs:4-7,28-29`: the module docs say "[`sections`] derives the sections of a turn", but that link resolves to the `sections` renderer module, not the derivation function. The `derive_sections` re-export points its doc at the private `section::sections`. The function is also exported under a different name from its definition, and `components/mod.rs` re-exports the `sections` module as `section_renderers`. Change: rename `section::sections` to `derive_sections` in `section.rs`, drop the `as` alias, and fix the first doc bullet to link `derive_sections`.
3. [nit] `src/components/turn_block/sections/stats.rs:27,32`: `tokens + 50` and `tokens + 50_000` overflow for counts near `u64::MAX`. That is a debug-build panic on (malformed) session data and a wrong value in release. Change: use `tokens.saturating_add(50)` / `tokens.saturating_add(50_000)`.
4. [nit] `src/components/turn_block/widget.rs:127-158,200-211`: `height()` and `render()` each run the full `layout()`. That includes markdown and syntect rendering, and for an unfolded tool call it includes `ToolOutput::text()`, which re-reads lazily stored output from disk. So a caller that asks for the height and then renders does all of this twice, and again on every frame. This is fine for this task, but task 018 will want a way to render from an already computed `BlockLayout` (e.g. `render_layout(&BlockLayout, area, buf)`), so that it can cache and stay within the §9.2 frame budget.
5. [nit] `src/components/turn_block/widget.rs:182-185`: `draw_interior` clones every span twice per row, once into `spans` and once via `Line::from(spans.clone()).width()`, just to compute the padding. Change: compute `pad` from `row.line.width() + 1` and clone only once (or just once into `spans`).
6. [nit] `src/components/turn_block/sections/tool.rs:30`: the unfolded tool description is char-wrapped. The description is prose, and §5.5 word-wraps prose (only commands and output are char-wrapped). The planner notes don't pin this down. Consider word-wrapping the description.
7. [nit] `src/components/turn_block/sections/thinking.rs:22`: the folded header takes `first_line` of the raw markdown source, so a first line like `**Plan**` shows its asterisks. Consider using the first rendered markdown line, or stripping inline markup.
8. [nit] `src/components/turn_block/sections/user.rs:22-27`: when the prompt's first paragraph fits on one line and a second paragraph follows, the second folded row is the blank paragraph separator. It renders as a lone `  …`, and because `ellipsize` takes `Style::default()` from an empty line, that `…` also has no `foreground` token (with `dim_unselected = false` it draws in the terminal's default colour). Consider skipping blank rendered lines when picking the two folded lines, or giving `ellipsize` a fallback style.
9. [nit] `src/components/turn_block/title.rs:72-90`: below width 5, `ellipsize(left, 0, …)` still emits `…`. The line becomes wider than the block, and `set_line` truncation cuts off the `─╮` corner. This is cosmetic and only at degenerate widths (no panic; `tiny_widths_do_not_panic` covers it).
10. [nit] `src/components/turn_block/widget.rs:200`: `Widget` is implemented only for `TurnBlock` by value. Since ratatui 0.26, the idiom is to also implement `Widget for &TurnBlock<'_>`, so that the transcript can reuse a configured block without cloning it.
11. [nit] `src/components/turn_block/widget.rs:136-139`: `layout()` silently skips a section whose renderer returns no lines (`if lines.is_empty() { continue; }`), but `derive_sections` still lists it. Markdown that renders to nothing, such as a prompt or assistant text that is only an HTML comment, would then be a section that task 018 can select but that has no rows. Change: drop such sections in derivation as well, or document that `section_rows()`, not `derive_sections`, is the source of selectable sections.
