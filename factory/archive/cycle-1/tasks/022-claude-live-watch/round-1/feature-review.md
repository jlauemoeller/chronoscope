VERDICT: FAIL

## Summary
The Claude loader now keeps a session live after the initial parse. It watches with `notify` and coalesces events over 100 ms. It reads appended bytes from the last offset and keeps a trailing partial line in a buffer. A shrink or inode change gives a `Reset` and a full re-parse. It also sends `Activity` with the file mtime, and falls back to polling when `notify` cannot start. Every acceptance criterion is implemented and tested, and the gates pass. Two must-fix findings remain. First, a failed reload stops the worker for good, which breaks the binding planner note "and continue watching". Second, the live-append tests use only generated lines, not the fixture sessions that §9.6 requires.

## Findings
1. [must-fix] `src/harness/claude/watch.rs`, `Watch::reload`, `Err(err)` branch: when the re-parse fails (an I/O error while reading the new file), the worker sends `Loaded` and returns `false`. `on_change` passes that up and the worker exits, so the session is never live again. This breaks the binding planner note: "send `ModelUpdate::Reset`, re-parse from the start … and continue watching". It is also the only failure path that kills the worker: a failed `File::open` or a `catch_up` error in `on_change` both return `true`. Keeping the old `streamer` is not a fix, because `Reset` and possibly a partial batch have already gone out, so its `sent_len`, `dirty` and offsets no longer match what the receiver holds. Change: after logging and sending `Loaded`, return `true`, and record that a full reload is needed. For example, use a `needs_reload: bool` flag, or make `streamer` an `Option<Streamer>` that is `None` after a failed reload. `on_change` must then take the reload path (`Reset` + `load_file`) on the next event or poll, whatever the size or identity. No test is required for the I/O-error path itself.
2. [must-fix] SPEC §9.6 guideline: "Adapter tests use fixture sessions … for each harness, including subagents, compaction and live append scenarios." Every test in `tests/claude_live.rs` builds synthetic one-block lines. None uses the existing fixtures in `tests/fixtures/claude/`, which `tests/claude_loading.rs` already loads through `fixtures()`. So nothing tests live appends with realistic content. That content includes split `message.id` lines with `apiBlockIndex`, held injected entries (flushed by `flush_held` on every `catch_up`), noise entries, a malformed line, and a >4 KiB `Read` result whose lazy byte range must come out right for appended lines (planner note: "with their byte ranges, for lazy tool outputs"). Change: add at least one test to `tests/claude_live.rs` that writes a prefix of `tests/fixtures/claude/session.jsonl` (cut mid-file, before the >4 KiB `Read` result), starts the worker and appends the rest. Split the rest in two writes with the first ending mid-line. The test then asserts that the turns from the applied updates equal `Assembler::from_file` on the full fixture. Do the same with `injected.jsonl`, cut between an injected entry and the entry that follows it. If the live result legitimately differs from a fresh parse there (held entries placed by `flush_held`), assert the documented difference explicitly instead of equality.
3. [nit] The planner note requires that incremental reads send `ParseWarnings` when the count changes (`Streamer::send_warnings` in `catch_up`), but no live test covers it. I mark it a nit because the acceptance criteria list the tests this task requires and this one is not among them. Finding 2's `session.jsonl` test, whose malformed line can be placed in the appended part, can cover it. Change: in that test, or a separate one, assert that `ParseWarnings(1)` arrives after the malformed line is appended. Then assert that a following valid append sends no second `ParseWarnings`.
4. [nit] `src/harness/claude/watch.rs`, `Watch::on_change`: the reload check uses only size and identity, as §7.1 specifies. If the same inode is truncated and then regrown past the old offset within one coalescing window (or one poll interval), the change is read as an append, and the read starts mid-content. This is within the spec's rule. Change (optional): document the limitation in the module docs. Alternatively, also reload when `meta.len() >= pos` but the byte at `read_pos() - 1` is no longer `\n`.
