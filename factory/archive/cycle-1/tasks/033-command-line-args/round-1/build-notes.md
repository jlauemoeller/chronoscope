## Changes
- `src/cli.rs` (new): the clap derive `Cli` (positional `SESSION_ID | PATH`, `--latest` conflicting with it, `--harness claude|opencode` case-insensitive, `--project`, `--theme`, `--config`) and `parse_args`. `lib.rs::run` passes the parsed `Cli` to `run_app`.
- `src/launch.rs` (new): the pure resolver `launch::resolve(request, working_dir, registered, index)` returning `Resolution { target, preselect, warnings }` or a `LaunchError` (messages are exactly what is printed after `chronoscope: `). Also `deepest_ancestor`, the "$PWD or its deepest ancestor" rule, now shared with the selector's preselection (`SelectorState::preselection`), and `HarnessIndex::read` (sync read of one harness's lists, via `index::collect`, now `pub(crate)`).
  - id: exact match wins over prefix matches; one match opens; several give `Target::Filtered` (lowest harness number first, newest first); none is an error. An empty argument matches nothing.
  - path: argument ending in `.jsonl` or an existing file. Missing path -> error; existing non-`.jsonl` file -> error; `--harness opencode` with a path -> error; Claude disabled in config -> error. (Decisions not in the plan, noted here.)
  - `--latest`: newest `started_at` over the projects at the deepest ancestor of `$PWD` (all harnesses with a project at that depth, or `--harness`), or over the `--project` matches.
  - `--project`: path (absolute or relative to `$PWD`, lexically normalised, compared by components) first, then display name/alias case-insensitively; at most one project per harness, lowest harness number first. No match -> warning (`--project: no project matches "x"`).
  - `--harness` alone -> tab preselection; warns when the harness is not enabled.
- Harness: new `Harness::open_file(path)` (default: error). `ClaudeHarness::open_file` scans the file, builds the `SessionSummary` (project and cwd from the entries) and registers it in an `Opened` map (`claude/subagent.rs`) that `resolve` consults first, so `load`, `subagent` and `subagent_info` work for a file outside the data dir; its subagents are looked up in `<stem>/subagents/` next to it.
- `AppInit::load_with_theme` (`--theme`): sets the theme id in the in-memory config only (never written); an unknown id gives the task-004 fallback plus a warning worded `--theme: unknown theme ...`. `startup_toast_text` omits the `Config: ` prefix for warnings whose key starts with `--` (command-line warnings).
- `--config` uses `Paths::with_config_file`; `AppInit.config_path` is that file, so the theme selector's save (task 031) writes to it.
- `app/runtime.rs`: `run_app(&Cli)` now resolves the command line (sync index read when `Request::needs_index`: a positional argument (id or path), `--latest` or `--project`; a path needs it so the header shows the project's display name) before `TerminalGuard::enter`, so errors go to stderr with exit code 1 and the terminal is untouched. `start_with` then gives the app the preselection hint, seeds the sync index as snapshots, and opens the session / filtered selector.
- `app/selector.rs`: `Preselect` hint honoured by `preselection()` (so later snapshots from the async index don't undo `--project`/`--harness`); filtered mode (`show_filtered`, `leave_filtered`, `push_filtered_results`, `SelectorMsg::LeaveFilter`): Sessions focused, rows are the sessions of the current harness whose id starts with the prefix, in the task-015 result-row format, titled ` Sessions matching "<prefix>" `, first selected; survives index snapshots; stats/active flags work for rows of other projects. `Esc` (via `SESSION_FILTERED_ATTR` on `SessionList`) leaves the filter and returns to the normal startup state (preselection, Projects focused, no session). Tab to Projects and `/` also end the filter. Several harnesses: the tab of the lowest-numbered harness with matches is shown; switching tabs lists that harness's matches.
- `app/browser.rs`: `open_session` split into lookup + `open_summary(harness, summary)` (public), used for direct opens of sessions the index may not list yet.
