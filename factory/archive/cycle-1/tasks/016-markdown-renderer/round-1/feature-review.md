## Findings
1. [nit] Some element styles are built from `Style::new()` or bare token styles instead of from `base`, although the planner notes say "every element style is derived from it". This covers the quote bar, table separators, header rule and horizontal rule (`Styles::muted` in `src/markdown/mod.rs`) and the code-block spans (`highlight_code` styles in `layout::code_lines`). As a result, base modifiers such as DIM or BOLD are lost on those elements. That matters later: a selected section is shown bold, and with `dim_unselected` (§8.2) an unselected one is dimmed. No acceptance criterion breaks today. Change: build `muted` as `base.fg(theme.role(Role::MutedForeground))`. Also decide (and document) whether code spans should take on the base modifiers, for example `base.patch(token_style)` with `fg` taken from the token.
2. [nit] The doc comment on `render_markdown` (`src/markdown/mod.rs`) says it returns "lines no wider than `width` cells". That is not true below the minimum widths given in the build notes. For example, `a_table_that_cannot_fit_shrinks_every_column_to_one_cell` asserts 5-cell lines at width 4, and deeply nested prefixes can also overflow. The widget clips these lines, so nothing renders wrongly. Change: state the limit in the doc comment (tables need about 1 cell per column plus separators, and each prefix needs its own width plus 1).
3. [nit] When a table row has fewer cells than there are columns, the row ends with a dangling separator, for example `| a | b |\n|---|---|\n| 1 |` renders `1 │ `. Change: in `table::row_line`, stop emitting separators after the last present cell, or trim trailing whitespace off the row.
4. [nit] `char_wrap` passes control characters such as a lone `\r` and ANSI `ESC[...m` sequences through unchanged. When raw tool output is drawn, this can throw off the cell count and the terminal. This is outside this task, but later tasks use `char_wrap` for tool output. Change: either sanitise control characters in `char_wrap` (replace them with a visible placeholder or drop them) or say in its doc comment that the caller must do it.
