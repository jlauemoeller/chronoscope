## Summary
The branch completes the Claude `Harness` with a streaming loader on a worker thread, a stop-on-drop `WatchHandle`, subagent linkage (meta `toolUseId`, then `toolUseResult.agentId`) with path-traversal-safe id resolution, and a `shell-words` based resume command. Every acceptance criterion has a test that would fail if the behaviour were wrong. The gate passes. I found no correctness, panic or security problems, only minor nits.

## Findings
1. [nit] `src/harness/claude/load.rs` `stream()` error branch (`Err(err) => { if streamer.has_unsent() { streamer.flush(); } ... }`): on a mid-file read error the partial flush skips `asm.flush_held()`, so injected entries the assembler is still holding are lost, and no `ParseWarnings` goes out before `Loaded`. The planner notes allow this ("On I/O error the worker logs the error, sends `Loaded`, and stops"; `ParseWarnings` is to be sent "with `Loaded`"). For a missing file the test rightly expects exactly `[Loaded]`. After partial output, though, a non-zero warning count is dropped. Change: in the error branch call `let updates = streamer.asm.flush_held(); streamer.note(updates);` before the flush, and optionally send `ParseWarnings(asm.unparsed_count())` before `run()` sends `Loaded`, so the partial view matches the clean-end path.
2. [nit] `src/harness/claude/load.rs` `Streamer::due()`: before the first `Appended`, a flush needs `new_turns > 0`. A transcript whose first turn only finishes after many MiB of metadata or noise therefore sends no `Progress` until then, and the §4.2 `Loading… N%` indicator stays at 0. Change (optional): before the first batch, also flush, and so send `Progress`, every `batch_bytes` even when there are no turns yet.
3. [nit] `src/harness/claude/subagent.rs` `info()`: a missing `agent-<id>.meta.json` is logged at `warn`. Subagents without a meta file (older Claude Code versions, or the `toolUseResult` fallback case) would warn every time the breadcrumb is built. Change: log `ErrorKind::NotFound` at `debug` and keep `warn` for other read errors and parse errors.
4. [nit] `src/harness/claude/subagent.rs` `find_by_result()`: the fallback reads the whole parent transcript (up to ~100 MB) on the calling thread every time it is called. The doc comment says this is not for the UI thread, which is fine for now. Task 027 should call `subagent()` off the UI thread, or the fallback should use the already-loaded parent model.
5. [nit] `src/harness/mod.rs` `WatchHandle.thread: Option<JoinHandle<()>>`: `new` always stores `Some` and nothing takes it, so the `Option` (and the `is_none_or` in `is_finished`) is never needed. Change: store a plain `JoinHandle<()>`, or add a comment if task 022 will need to `take()` it.
6. [nit] `src/harness/claude/resume.rs` `build()`: `{id}` is replaced only in the arguments, not in the program word. This matches the planner note ("in every argument"), but a template like `{id}-runner` would pass a literal `{id}` program name without any warning. Optional: substitute in the program too, or document the limitation on `with_resume_command`.
7. [nit] `src/harness/claude/load.rs` `Streamer::read_all()`: it reads until `read_until` returns 0, and it passes a final line without a newline to `push_line` as if it were complete. `a_last_line_without_a_newline_is_parsed` locks this in. That is right for a finished file. On a session Claude Code is still writing, an entry caught mid-write is counted in `ParseWarnings` and its bytes are consumed, and the worker can also read past the `total` measured at open. This is harmless before live watching exists. Task 022 should keep a trailing partial line unconsumed (`Assembler::push_chunk` / `buffered_from` already do this) and limit the initial parse to `total`.
8. [nit] `tests/fixtures/claude/subagents/` is hand-written, not a "trimmed real session, scrubbed" (SPEC §9.6, and the AC's "scrubbed subagent directory"). Every other Claude fixture in `tests/fixtures/README.md` is also hand-written, earlier rounds accepted that, and the README documents the origin and the real 2.1.x layout it follows, so this is not a new breach. It would still be worth checking a trimmed real subagent directory into the suite before release.
