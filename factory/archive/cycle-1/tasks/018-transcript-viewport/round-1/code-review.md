## Findings
1. [nit] `src/components/transcript/mod.rs` (`refresh`) and `window.rs` (`Window::build`): every one-row `Cmd::Scroll` runs `TurnBlock::layout` again for every visible block, because the window is rebuilt from scratch and the cache holds only heights. With one very large unfolded block on screen (a long markdown reply, or tool output before task 019's truncation), each scroll tick re-wraps the whole block, which puts the SPEC §9.2 16 ms frame budget at risk. The bottom-of-transcript case lays out twice: `build_clamped` builds, clamps, then builds again. Change: when only the offset changed (no content, fold, selection, dim or theme change), reuse the previous window's `Placed.layout`s for the block indices that overlap both windows, and lay out only the newly exposed blocks. Clamp the offset before the first `build` so that it never runs twice.
2. [nit] `src/components/transcript/mod.rs`: test instrumentation is part of the public API. This covers `Transcript::layouts_run`, `Transcript::cache`, `Transcript::visible_blocks`, the `pub use cache::{LayoutCache, Located, Measure}` re-export, and `LayoutCache::computed` and `LayoutCache::known_height` in `cache.rs`. Change: make these `pub(crate)` (or `#[cfg(test)]` where only tests use them), and drop the `pub use` of the cache types unless the App needs them.
3. [nit] `src/components/transcript/mod.rs` (`window_for`): when `view` gets an area that no viewport was announced for, the fallback clones the whole `LayoutCache` every frame. On a width mismatch it also measures every block above the offset again, and it reads an offset meant for the old width as one for the new width. This is documented and free of side effects, but it is easy for the App (task 021) to fall into without noticing. Change: add a `debug_assert!` or a `tracing`/log warning on the fallback path, so that a missing `VIEWPORT_ATTR` shows up in development.
4. [nit] `src/components/transcript/nav.rs` (`scroll_to`): the method checks `self.offset == before`, returns `NoChange`, and otherwise calls `outcome(before)`, which repeats the same comparison and can only return `Changed`. Change: return `CmdResult::Changed(self.state())` directly in the else branch (or fold both into `outcome`, with `outcome` returning `NoChange` rather than `Visual` when nothing changed, if that is the intent).
5. [nit] `src/components/transcript/nav.rs` (`move_selection`): when there is no cursor, the method calls `ensure_selection()` and then returns `CmdResult::NoChange`, even if a selection was just made. Change: return `CmdResult::Visual` when `self.content.selected` changed from `None` to `Some`.
6. [nit] `src/components/transcript/updates.rs` (`change_turns`, `sections_if`): types are spelled out with inline paths in signatures (`super::content::Content`, `super::content::Changes`, `crate::model::TurnId`). Change: import them with `use` at the top of the module.
7. [nit] `src/components/transcript/content.rs` (`Content::append`): an `Appended` turn whose id already exists replaces the existing turn in place, while `ModelUpdate::apply` in `src/model/mod.rs` appends a duplicate. Change: align the two, or document on `ModelUpdate::Appended` that a repeated id is treated as an update.
8. [nit] `src/components/transcript/updates.rs` (`change_turns`): when an `Updated` turn above the viewport changes height, the numeric offset is kept, so the visible content jumps. For example, a tool result arriving in a block that has scrolled off the top moves everything on screen. Change (here or in task 022): if the replaced block's index is below the top visible block, adjust `self.offset` by the change in that block's height so that the top visible row stays put.
9. [nit] `src/components/transcript/tests/cache_lookup.rs` (`locate_is_a_binary_search_over_known_prefix_sums`): `start` is updated but never used in any assertion (dead test code). The test also checks only that no measure calls are made, not that the search is a binary search. Change: remove `start`, and rename the test to something like `locate_with_known_heights_measures_nothing`.
10. [nit] `src/model/mod.rs` (`ModelUpdate::Reset` doc): "the App forwards it like `Appended`" describes App behaviour that does not exist yet (the Transcript is not mounted). Change: word it as the intended contract ("the App is to forward it…"), or leave the App's role to task 022.
