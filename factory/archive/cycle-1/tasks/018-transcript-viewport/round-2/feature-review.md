## Findings
1. [nit] `src/components/transcript/window.rs` (`Window::build_clamped`) together with `mod.rs` (`refresh_scrolled`). This is carried over from round 1. Round-1 code-review nit 1 asked for two things: reuse layouts on scroll, and clamp the offset before the first `build` so it never runs twice. Only the first was done. The reuse makes the second part worse: the first `build` takes the reused layouts out of `Measurer::reuse`, so after the clamp the second `build` lays out every visible block again. At the bottom of the transcript, every `Cmd::Scroll(Down)` that ends as `NoChange` therefore re-lays out the whole window. One example is holding `j` at the end of a live session. `scrolling_lays_out_only_the_newly_exposed_blocks` only scrolls in the middle of the transcript, so it does not catch this. Change: in `build_clamped`, run `cache.clamp_offset` first and then a single `build`, so the reused layouts survive. Add a counter assertion for a scroll at the bottom.
2. [nit] `src/components/transcript/updates.rs` (`invalidate_replaced`): the offset is adjusted only for replaced blocks with `index < top_block`. If the top visible block is itself replaced and grows above the offset (for example, a tool result arrives in a section scrolled off the top of a partly visible block), the screen still shifts. The spec does not require this. Change (optional, or in task 022): for `index == top_block`, keep the row of the first visible section fixed.
3. [nit] `src/components/transcript/tests.rs` (`scrolling_lays_out_only_the_newly_exposed_blocks`): `let mut exposed = 0; exposed += …` is an odd way to bind a single value. Change: `let exposed = t.visible_blocks().end - visible.end;`.
4. [nit] `src/components/transcript/updates.rs` (`restore_selection`): the early-return branches (`ensure_selection` when nothing is selected, and `first_section_from(0)` when the selected turn is gone) do not call `reveal_selection`. In practice the second branch cannot be reached, and the first one selects near the top. Change: call `reveal_selection()` in those branches too, for consistency.
