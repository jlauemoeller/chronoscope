## Findings
1. [nit] `src/components/turn_block/renderers/tool/read.rs:17-25` (`ReadBody` doc comment): it still lists only Claude's numbering (`     1→text`, `1<TAB>text`). It does not mention OpenCode's `N: text` prefix or the leading `Read file …`/`Read directory …` line that is now dropped. Change: add both to the doc comment, e.g. "…or OpenCode's `1: text`; OpenCode's leading `Read file <path>, lines a-b` / `Read directory …` line is not content and is left out."
2. [nit] `src/harness/opencode/load.rs:173` (`text_at`): this is a database-reading helper, but it lives in the loader, and `subagent.rs` imports it from `super::load`. Change: move it to `src/harness/opencode/db.rs` next to the other row helpers, as `pub(super) fn text_at`, and import it from there in both `load.rs` and `subagent.rs`.
3. [nit] `src/harness/shared.rs:23-27` (`SubagentInfo`): the type is now harness-neutral, but its doc comment ("What `agent-<id>.meta.json` says…") and its `#[serde(rename = "agentType")]` are Claude-specific. OpenCode builds it from the `subagent` tool part. Change: reword the doc as "The agent type and description of a subagent run (Claude: from `agent-<id>.meta.json`; OpenCode: from the `subagent` tool part's input)", and keep the serde attribute with a comment saying it serves the Claude meta file.
4. [nit] `src/harness/opencode/db.rs:266` (`a_relative_path_is_made_absolute`): the length comparison is an indirect check. Change: assert the exact value instead, e.g. `assert_eq!(immutable_uri(Path::new("opencode.db")), immutable_uri(&cwd.join("opencode.db")))`.
5. [nit] (carried over from round 1) `src/harness/opencode/assemble.rs` (`result`): tool results are always `ToolOutput::inline`, so large OpenCode outputs stay in memory instead of being re-read on demand (SPEC §9.2). The planner notes don't require a SQLite output source. Change (follow-up task): add a SQLite `ByteSource`/`LineFormat` and build large results with `ToolOutput::from_text`.
6. [nit] `src/components/turn_block/renderers/tool/read.rs:69-71` (`is_opencode_header`): the check runs on every Read result, from any harness, and matches only on the prefix. A plain, unnumbered result whose first real line starts with `Read file ` would lose that line. All 2298 real OpenCode headers end in `, lines a-b` or `, entries a-b`. Change: also require that suffix, e.g. `(line.starts_with("Read file ") && line.contains(", lines ")) || (line.starts_with("Read directory ") && line.contains(", entries "))`, or match `rsplit_once(", ")` followed by `lines `/`entries ` and a `\d+-\d+` range.
7. [nit] `src/components/turn_block/renderers/tool/read.rs` (layering): the knowledge of OpenCode's result framing now lives in a shared component. SPEC §5.1 says adapters translate native formats into the shared model. This is not a breach, because `ToolResult` holds raw tool output for both harnesses and the renderer already parses Claude's `→`/TAB numbering. But a third harness's format would land here too. Change (optional): leave it, or move the header strip into `opencode/assemble.rs` for `read` tools so that the renderer sees only line-numbered content.
