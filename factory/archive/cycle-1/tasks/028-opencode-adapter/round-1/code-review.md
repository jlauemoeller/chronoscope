## Findings
1. [nit] `src/harness/opencode/assemble.rs:515` (`result`): every tool result is stored with `ToolOutput::inline`. SPEC §9.2 says large tool outputs keep only line counts and a source reference until they are unfolded, searched, copied or exported. The builder documents this as a known limitation (`LineFormat`/`ByteSource` only describe byte ranges of Claude JSONL files). It is not must-fix here: the task's planner notes and acceptance criteria don't ask for it, and the data is held once, so the §9.2 memory budget isn't at risk. Change (follow-up task): add a SQLite output source, e.g. `ByteSource::Sqlite { db, message_id }` plus `LineFormat::OpenCode { part_id }`, and build large results with `ToolOutput::from_text(text, || source)` so they are re-read on demand through `Db::select`.
2. [nit] `src/harness/opencode/db.rs:52` (`Db::open`): the `immutable=1` retry runs after any failure of the first open or probe, including `SQLITE_BUSY` (after rusqlite's 5 s busy timeout) or a transient I/O error. In immutable mode SQLite ignores the WAL and assumes the file never changes. On a live OpenCode database that can return stale rows or `SQLITE_CORRUPT`. Change: retry only for the error classes the fallback is meant for (`ErrorCode::CannotOpen` and `ErrorCode::ReadOnly`/`SQLITE_READONLY_*` from the probe), and return any other error as is.
3. [nit] `src/harness/opencode/tests.rs:117` (`a_full_load_leaves_the_database_file_and_its_directory_unchanged`): the fixture uses rollback-journal mode, but real OpenCode databases use WAL. I checked SQLite's behaviour: a read-only open of a WAL database whose `-wal`/`-shm` are absent, in a writable directory, creates both files and leaves them behind. The planner accepted relying on SQLite's side files, so this is not a breach, but the test never covers the real mode. Change: add a WAL-mode variant (`db.exec("PRAGMA journal_mode = WAL;")` while a writer connection keeps the `-wal` present, or after a checkpoint) that runs the same full load and asserts the `.db` bytes are unchanged.
4. [nit] `src/harness/opencode/tests.rs:152` (`a_database_that_cannot_be_opened_read_only_is_read_as_immutable`): when the test runs as root (e.g. in some CI containers), `can_write` is true and the `OpenMode::Immutable` assertion is silently skipped. Change: print a message when the assertion is skipped, or assert `can_write == false` unless running as root (`libc::geteuid` is unavailable without a crate, so a skip message is enough).
5. [nit] `src/harness/opencode/db.rs:161` (`immutable_uri`): a relative path such as `opencode.db` becomes `file:/opencode.db`, which points at the filesystem root. Config paths are tilde-expanded but may still be relative. Change: prepend `/` only when the path is absolute with a drive letter (Windows). Otherwise make the path absolute first, e.g. with `std::path::absolute`.
6. [nit] `src/harness/opencode/subagent.rs:31`, `:135`: `find_part` and `info` read `data` with `row.get::<_, String>(0)`. If any matching row stores `data` as a BLOB, the whole lookup errors, while the loader (`load.rs` `fetch_page`) accepts BLOB data. Change: read `data` through the same `ValueRef` text/blob handling as `fetch_page`, factored into one helper.
7. [nit] `src/harness/opencode/load.rs:169` (`fetch_page`): `other => match other { ValueRef::Integer .., ValueRef::Real .., _ => .. }` is a nested match inside the outer one. Change: put the `Integer`/`Real` arms in the outer match and drop the inner `match`.
8. [nit] `src/harness/opencode/subagent.rs:24`: the doc comment says `find_part` returns the part "with the row's `time_created`", but it returns only the part. Change: drop "with the row's `time_created`".
9. [nit] `src/harness/opencode/tests.rs:583`: the comment "Three rows: 09:05:01 .. 09:05:40" contradicts the assertion `message_count == 2` below it. The turn has two assistant rows; the third row is the trailing `synthetic` one. Change: change the comment to "Two rows".
10. [nit] `src/harness/opencode/discovery.rs:91` (`with_page_size`): it is `#[doc(hidden)] pub`, but only in-crate tests call it. Change: make it `#[cfg(test)] pub(crate)` so it stays out of the public API.
