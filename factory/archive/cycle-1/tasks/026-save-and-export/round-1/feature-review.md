## Findings
1. [nit] **Security.** A dangling symlink can get past the harness-data refusal. `resolved()` in `src/app/save.rs` canonicalises the longest existing prefix. For a path whose last component is a symlink to a not-yet-existing file in `~/.claude/projects/...`, `canonicalize` fails on the full path, so the check runs on `<parent>/<link-name>` and passes. `path_chosen` sees that the link exists (`symlink_metadata` is `Ok`) and asks to overwrite. On `y`, `std::fs::write` follows the link and creates a file inside harness data. This needs a pre-planted symlink plus a confirmation, so the practical risk is low. Change: in `resolved()` (or in `is_harness_data`), when `path.symlink_metadata()` shows a symlink, resolve its target with `std::fs::read_link` (joined onto the link's parent if relative) and check that path too, repeating for chains. Add a `#[cfg(unix)]` test with a dangling link into the protected dir that expects `Refusing to write into harness data`.
2. [nit] Folded-export summaries are not HTML-escaped. The golden shows `> Read the <dump> & friends`, and GitHub-flavoured renderers treat `<dump>` as raw HTML and hide it. The `<details>` summaries are escaped. Change: in `section_markdown` (`src/components/turn_block/export.rs`), escape `<`/`&` in the folded-summary path (`quote` of `displayed_text`), or backslash-escape markdown-significant leading characters. Update the golden.
3. [nit] `Msg::Export { full, .. }`: `full` is never used by the App (`src/app/mod.rs`, the `Msg::Export { full: _, document }` arm). Change: drop the field, or use it (for example in a log line). The transcript tests do assert on it, so keeping it is defensible.
4. [nit] `E` reads every lazy tool output from disk synchronously on the UI thread when the key is pressed, before the user has even confirmed a path. This is fine for typical sessions but could stall on very large ones (§9.2). Change, optional: no action needed for this task, but consider noting it in `doc/save-and-export.md` as a known cost.
