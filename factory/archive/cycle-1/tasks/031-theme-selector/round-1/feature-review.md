## Findings
1. [nit] The task's acceptance criterion and UI state 5 ("12 themes at 60x20 … list scrolled") contradict the planner's binding height rule `min(h − 2, rows + 5)`: 12 themes need 17 rows, and 60x20 allows 18. The builder kept the formula, added the boundary test `twelve_themes_fit_exactly_at_60x20`, and used 16 themes for the scrolled snapshot. Change: none in the code. The planner should correct the example in task.md (for example to "16 themes at 60x20" or "12 themes at 60x16") so later rounds and tasks don't trip on it.
2. [nit] `src/app/browser_tests/theme_selector.rs:14-58`: `every_id_is_themed_but_the_global_events` keeps its own copy, `THEMED_IDS`, and only asserts `true` for each entry of that copy. It would not catch a new `Id` that is added to `THEMED_IDS` but left out of the production `THEMED` in `src/app/theme_selector.rs:29`. Change: make `THEMED` `pub(super)` and assert that the test's set equals `THEMED` (or iterate over `THEMED` directly in the exhaustive match), so the two lists can't drift apart.
