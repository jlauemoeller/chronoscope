## Findings
1. [nit] AC "With more themes than fit (12 themes at 60x20), the list scrolls" and UI snapshot 5 contradict the binding layout rule `height = min(h − 2, rows + 5)`: 12 + 5 = 17 rows, and 60x20 allows 20 − 2 = 18, so 12 themes fit without scrolling (and 60x20 is already the minimum drawable size). The builder kept the formula, proved the boundary with `twelve_themes_fit_exactly_at_60x20` (all 12 visible through `App::view`, overlay exactly 17 rows) and took the scrolled snapshot with 16 themes at 60x20 (`sixteen_themes_at_60x20_scroll_with_the_cursor_near_the_end`: Default/Terminal scrolled off the top, cursor on User 08, User 09 hidden below). Nothing in the code needs to change. For the Approver/Planner: accept the deviation, or fix the task text (e.g. "12 user themes", or "16 themes").
2. [nit] `src/config/edit.rs` `restore_line_endings` — when a `theme` key has to be added to a file with mixed line endings (some `\r\n`, some bare `\n`), every `\n` becomes `\r\n`, so "everything else byte-identical" no longer holds for that file. Change: convert only when the original has no bare `\n` (e.g. `original.matches('\n').count() == original.matches("\r\n").count()`), or splice the new `theme = "<id>"` line into the original text instead of re-rendering the whole document.
3. [nit] `src/config/edit.rs` test `a_theme_that_is_not_a_value_is_replaced` locks in that a user's `[theme]` table (with its keys and comments) is silently deleted and replaced by `theme = "<id>"`. That config shape is invalid anyway, so this is acceptable, but consider logging a warning in `with_theme` when a non-value `theme` item is overwritten, so the user can find out what happened to the table.
4. [nit] `src/app/theme_selector.rs` `THEMED` and the test list `THEMED_IDS` in `src/app/browser_tests/theme_selector.rs` are two separate lists. The exhaustive `match` in `every_id_is_themed_but_the_global_events` guards only the test copy, so a future themed `Id` missing from the production list is caught only if some test mounts that component. Change: make `THEMED` `pub(super)` and have the test iterate it (or replace both with one `fn is_themed(Id) -> bool` with an exhaustive match).
5. [nit] `src/components/mod.rs:50` — `MIN_WIDTH as THEME_SELECTOR_MIN_WIDTH` is re-exported but nothing outside the module uses it. Change: drop the re-export, or use it in place of the literal `41` in the layout/app tests.
6. [nit] `src/app/theme_selector.rs` `open_theme_selector` doc comment says it does nothing "when it, or another overlay or prompt, is open", but it does open over the session selector overlay, which is correct per §6.6. Change: say "when it, the help overlay or a prompt is open".
7. [nit] `src/config/edit.rs` `save_theme` writes in place with `std::fs::write`, so a crash or full disk mid-write could leave a truncated config. This is low risk for a tiny file, and an in-place write keeps symlinked dotfiles intact. If you want it atomic, write a sibling temp file and rename it over the canonicalised target path.
