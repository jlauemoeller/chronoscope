## Changes
- `src/components/transcript/mouse.rs` (new): the transcript's mouse handling. A wheel step is `Cmd::Custom(WHEEL_UP/WHEEL_DOWN)` through `perform`, so it takes the page keys' path (`scroll_pages` with `Amount::Rows(3)`): the selection follows to the topmost fully visible section, following/`↓ N new` update. A left press maps the row to a block and a row of the block through the prepared window (layout cache blocks) and to a section: borders, padding columns, blank rows and rows below the last block select nothing; the first row of a foldable section (summary line or marker cells) selects and toggles via `fold_command(Toggle)` (so the search's temporary unfold becomes explicit, as with `Enter`); a `… N more lines` row expands the output (same path as `Enter`); any other row selects without toggling and without scrolling.
- `src/components/transcript/{keys,paging,mod}.rs`: `WHEEL_UP`/`WHEEL_DOWN`/`WHEEL_ROWS` (3), `Amount::Rows`, `on()` handles only the routed `UserEvent::Mouse` (the raw `Event::Mouse` the focused component also gets is ignored).
- `src/components/help_overlay/mod.rs`: the wheel scrolls 3 rows (`Msg::HelpScrolled`); clicks do nothing.
- `src/components/theme_selector/mod.rs`: a click on a selectable theme row moves the cursor and says `Msg::ThemeClicked(id)`; the wheel moves the cursor one theme (`PreviewTheme`); other cells do nothing.
- `src/app/mod.rs`: new `Msg::ThemeClicked(String)`.
- `src/app/mouse.rs`: `topmost_overlay`; `route_mouse` now handles points outside the topmost overlay (left press closes with the `Esc` message: `CloseHelp`, `CancelTheme`, `CloseSelector` only for `Screen::BrowserSelector` and not during the resume confirmation; wheel ignored; no exception for the toast); `takes_mouse` lets the help overlay, theme selector and (when no prompt is open) the transcript / top subagent transcript take the mouse; a left press on the transcript focuses it; `theme_clicked` (single click previews, double click within 400 ms with the injected clock selects like `Enter`).
- Decisions where the task was silent: the help overlay wheel step is 3 rows (as the transcript); with a prompt open (search, path, `y/n` resume) the transcript ignores the mouse (as 034 treats the prompt as modal for the selector's panes); a click outside the selector over a session closes it also while the search prompt is open (`CloseSelector` unmounts the prompt and ends the search), but not during the modal resume confirmation; the transcript's content columns are 2..width-4 (columns 0, 1 and the right padding/border are not hits).
- Tests changed because the rules changed: `nothing_under_the_help_overlay_or_the_theme_selector_gets_the_mouse` (now clicks the pane cells the overlay covers), and the browser test that clicked the header above the selector (an outside click now closes the selector) uses the frame between the panes. The outside-the-overlay update tests aim at a `▶` summary row of the transcript beside the overlay (and use a 200x50 terminal for the selector, whose overlay covers the whole transcript at 120x40), so they fail if the transcript got the event; `the_browser_alone_takes_no_mouse_yet` is replaced by the transcript tests.
