## Summary
The keys go through the `browser` keymap. `j`/`k` paging, page scrolling with selection follow, start/end, the fold keys with the screen-row anchor, and the `s` toggle are all implemented cleanly and well tested. All nine required snapshots are present and accepted, and the test gate passes. One real bug remains: `]`/`[` can leave the selection off screen. When the jumped-to block starts with a tall system section, the selected prompt sits below the viewport, which breaks SPEC §6.3 "Selecting a section scrolls it into view".

## Findings
1. [must-fix] `src/components/transcript/paging.rs`, `jump_turn` (the `if self.viewport.is_some() { self.offset = ... cache.top(block, m) }` lines). The offset is always set to the block's top border, but the selected section is the block's first *non-system* section. When an unfolded system section taller than the viewport comes before the prompt, the prompt is selected off screen. This breaks SPEC §6.3 ("Selecting a section scrolls it into view"). The planner's "top border at the top *when possible*" only applies while the selection still fits. It is easy to reach: `+` unfolds system sections too, and a `file` or `instructions` attachment shows its full text when unfolded.
   - Reproduced in a scratch copy at 80x10 with `[prompt("p1"), user "u2" = blocks::user("The prompt.", vec![blocks::injected("i1", &[("file", <40 lines>)])]), reply("r1")]`. Pressing `+` then `]` selects `u2/Prompt` at rows 50..51 with `offset == 5`.
   - Change: after setting the offset to the block top, check whether the selected section's span still lies within `[offset, offset + height)`. If it does not, scroll it into view with `nav::reveal(self.offset, height, &span, Reveal::Top)`, using `self.cursor()` and `self.span(..)` as `reveal_selection` does. Then `refresh()`. The top border stays at the top whenever the selection fits.
   - Add a regression test in `src/components/transcript/tests/keys.rs` shaped like the repro above. It must assert that the selected section is fully inside the viewport after `+` and `]`, and likewise for `[` coming back from a later block.
2. [nit] `src/components/transcript/mod.rs`, `AppComponent::on`. The `CmdResult` of `perform` is thrown away and `on` always returns `None`. The App redraws only when a `Msg` arrives: `App::request_redraw` is called from `update`, and the `Prompt` sends `Msg::PromptMoved` only to get a redraw. So once the browser (task 021) mounts the `Transcript`, navigation keys will not redraw the screen. Nothing mounts the transcript yet, so this is not a defect of this task, but the contract is defined here. Change (here or in 021): return a redraw-triggering `Msg` (e.g. `Msg::TranscriptChanged`) when the result is `Changed`/`Visual`, or record the follow-up for task 021 explicitly.
3. [nit] `src/components/transcript/tests/keys.rs`, `the_screen_row_is_kept_only_when_the_end_of_the_transcript_allows_it`. `assert!(t.offset() <= total - 24)` always holds after clamping, so the test cannot fail. Change: assert the expected value instead. With the last section selected at the end, `offset == total - 24` after `+`, and the selected section's screen row is the clamped one.
4. [nit] `src/components/transcript/nav.rs`, `Cursor`. The fields `rows` and `pos` were widened to `pub(super)`, but nothing outside `nav.rs` uses them; only `block` and `id()` are needed. Change: keep `rows` and `pos` private.
5. [nit] `src/components/transcript/paging.rs`, `jump_to_start` / `jump_to_end`. These duplicate `first_section_from(0)` and `last_section()` in `updates.rs`. Change: make those helpers `pub(super)` and reuse them.
6. [nit] `src/components/transcript/paging.rs`, `is_system` / `turn_stop`. `is_system` calls `derive_sections` on the whole turn again for every candidate section, so a jump grows with the square of a block's size. Change: in `turn_stop`, derive the block's sections once, collect the ids of the `SectionKind::System` ones, and pick the first id from `sections_of(index)` that is not among them.
7. [nit] `src/components/transcript/folding.rs` `FoldOp` and `src/components/transcript/paging.rs` `Amount` are `pub` inside private modules. Change: make them `pub(super)` to match the other new items. Also, `keys.rs` `custom` uses the inline path `super::folding::FoldOp::Fold`/`Unfold`. Change: import `FoldOp` with a `use` (`mod.rs` likewise uses `folding::FoldOp::Toggle`).
