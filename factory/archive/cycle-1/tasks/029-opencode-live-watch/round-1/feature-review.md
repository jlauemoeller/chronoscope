## Findings
1. [must-fix] `tests/opencode_live.rs` `ten_quick_writes_are_coalesced` cannot detect a missing debounce. The ten `rewrite`s go out back to back with `synchronous = OFF` and finish in well under a millisecond. A worker without any debounce wakes on the first event, and by the time its single refresh runs it already sees the final state. Later events find an unchanged hash and emit nothing.
   - Mutant check: in a scratch copy I set `DEBOUNCE` and `MAX_WAIT` in `src/harness/opencode/watch.rs` to `Duration::ZERO`. The test still passed in 9 of 9 runs.
   - Change:
     - In the test's loop, add `std::thread::sleep(Duration::from_millis(30))` after each `env.rewrite(...)`. That gap is below the 200 ms debounce, and the total of about 300 ms stays under the 1 s `MAX_WAIT` cap.
     - Tighten the assertion to `assert!((1..=3).contains(&batches), ...)`. The slack covers the watcher's catch-up pass, which can overlap the first write.
   - I tried this change in the scratch copy. The no-debounce mutant gives 10 batches and fails, 3 of 3 runs. The real code gives 2 batches and passes, 5 of 5 runs.
2. [nit] `src/harness/opencode/watch.rs` `MAX_WAIT` (1 s cap since the first event) departs from the binding planner note: "wait until 200 ms have passed without further events, then process once". SPEC §7.1 only says "debounced 200 ms", no AC depends on the pure trailing form, and the cap keeps a message that streams without pause visible. So I consider it acceptable. I'm listing it so the Approver sees the deviation explicitly. No change needed beyond keeping the module doc that explains it.
3. [nit] `follow.rs` `Follower::step` calls `self.asm.finish()` at the end of every pass, which flushes held `synthetic`/`system` entries into the current turn.
   - Problem: if an injected row and the `user` row it precedes land in different passes, the entries stay in the previous turn. SPEC §5.6 / line 285 says "in the next turn when it precedes a prompt". A reload would then place them differently from the live view. This is possible with the 1 s poll, or when a write straddles the debounce; it is rare with `notify`.
   - Change (optional): remember the item that the last pass's `finish()` flushed into the current turn. If the next pushed row is a `user` row, move that item to the front of the new User turn (`Updated` for the old turn, `Appended` for the new one). Add a `replace_tests`-style test against `assemble()`. Otherwise, add this to the documented known limits.
4. [nit] `follow.rs` step 1 selects the full `ROW_COLUMNS` (including `data`) for every row with `time_updated >= max_updated` on every pass, and always re-reads the newest row. The planner note asked for `SELECT id, time_updated …` first, then reading `data` only for rows that changed. While a large tool output streams, this repeats a full read and hash of `data` on every pass. To keep the same-millisecond detection, consider selecting `id, time_updated, length(data)` (or similar) first, then fetching `data` only for rows whose time or length moved.
5. [nit] The polling `Signature` in `follow.rs` (`max(seq)`, `max(time_updated)`, `count`, session times) misses a data-only rewrite within the same millisecond, which the notify path catches through the data hash. This is acceptable for a fallback. Mention it in the doc comment of `Signature`.
6. [nit] Known limits, listed so they are visible:
   - Rows deleted by OpenCode (for example a revert) never produce a `Reset`.
   - A new part of a non-latest row is appended at the end of its turn.
   - `synthetic`/`system` rows updated in place are not re-read.
   - A row whose `data` was unparsable when first pushed has no `row_turn` entry. If it later becomes valid, `Assembler::replace_row` ignores it ("not seen before"), so it is never shown and stays counted in `ParseWarnings`.

   Consider routing a seen-but-unparsed row through `push_row` handling in `replace_row`, or at least documenting it with the others.
7. [nit] `src/harness/opencode/discovery.rs`, the doc comment on `fn load` (around line 264): the line "[`watch`](super::watch)) and sends what changes. A session that cannot be found or read ends in" is longer than the surrounding comment lines (rustfmt does not wrap comments). Re-wrap it.
