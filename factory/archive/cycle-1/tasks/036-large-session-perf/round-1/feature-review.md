## Findings
1. [nit] Expanding an unfolded 2 MB output past its truncation (`Enter` on the `... N more lines` row) takes 22–33 ms, because every line of the block is laid out at once. That is above the §9.2 figure of "each frame rendered in under 16 ms" for that single interaction. The AC measures 100 scrolled frames, which pass, and the builder reports this openly as a "reference" line in `tests/budgets.rs` and in `docs/performance.md`, so it is not an AC failure. Change: none needed for this task. Consider a follow-up task that lays out an expanded tool output in windows/chunks (or lazily per visible line range), so that the expand step also stays under 16 ms.
2. [nit] The materialisation test (`src/bench_support/tests.rs::loaded_transcript`) does not run the real loader. Because the counters are thread-local, it copies the loader's work on the test thread with `push_chunk` and calls `flush_held` after every chunk. The real `Streamer` in `src/harness/claude/load.rs` calls `push_line` and runs `flush_held` only at `finish`/`catch_up`. The assembler and `Transcript::apply_update` code paths are the same, so the test still works. However, a later change in `Streamer` that materialised an output would not be caught. Change (optional): make `TEXT_CALLS`/`SOURCE_READS` process-wide `AtomicUsize` counters under `cfg(test)`, and add a test that loads through `ClaudeHarness::load` (for example via `load_turns`/`load_transcript`) and asserts that neither counter moved.
3. [nit] `src/bench_support/mod.rs::cached_fixture` reuses a cached file whenever the `complete` marker exists and the size is at least the target. It relies on someone remembering to bump `GENERATOR_VERSION` when `generate.rs` changes, and otherwise stale fixtures get measured silently. Change (optional): extend the doc comment on `GENERATOR_VERSION` to say it must be bumped on any change to `generate.rs`, or key the cache on a hash of the first few KiB generated for the seed.
4. [nit] The new doc lives in `docs/performance.md`, while all the other project docs are in `doc/`. This follows the task text and the build notes flag it, so nothing is required. Change (optional): if the planner agrees, move it to `doc/performance.md` and update the path in the comment in `.github/workflows/ci.yml` and in the `tests/budgets.rs` header.
