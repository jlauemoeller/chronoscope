## Findings
1. [nit] `ModelUpdate::Reset` does not re-check the empty state. In `src/app/browser.rs` `session_update`, the `Updated(_) | ModelUpdate::Reset` arm only forwards the update, so after a `Reset` on a loaded session that leaves zero turns, the transcript area is blank rather than showing `Session file is empty`. No harness sends `Reset` yet, so this only matters once live updates arrive (tasks 022/023). Change: call `self.refresh_session_empty()` after forwarding `Reset`, with a small update test (`Loaded` with turns, then `Reset` → `session_is_empty()`).
2. [nit] When `harness.load` fails, `open_session` has already dropped the previous `WatchHandle`, so the old browser stays on screen but is no longer live, and only a toast reports the failure. The planner's drop-then-load order allows this and the build notes document it. Change: none now; once the `● live` marker lands (task 023), make sure it reflects the stopped watch in this case.
3. [nit] `src/app/browser.rs`, in `open_session`: `self.browser = super::browser::BrowserState { .. }` names the module's own type through `super::browser::`. Change: write `BrowserState { .. }`.
4. [nit] `src/app/runtime.rs`, imports: `use std::sync::Arc;` sits between the `super::` and `crate::` imports, separated by blank lines. Change: move it up with the other `std` imports.
