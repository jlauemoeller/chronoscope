## Findings
1. [nit] `KeySpec::to_event` (`src/keymap/key.rs`) returns the *normalised* event, with SHIFT removed from characters and `BackTab` without SHIFT. Its doc comment says it is "for subscriptions that need one". A later `GlobalEvents` that subscribes with an exact `EventClause::Keyboard(spec.to_event())` would miss `Char('?')` + SHIFT, which many terminals send for `?`. Change: in the doc comment, state that the event is normalised and that subscribers must also cover the SHIFT variant for characters (or subscribe broadly and filter through `Keymap::resolve`). Alternatively, add a helper that returns all event variants a key should match.
2. [nit] `ctrl-C` and `ctrl-shift-c` parse to `Char('C')` + CONTROL. `is_ctrl_c` does not catch this, so the binding is accepted, but terminals with legacy encoding report it as `Ctrl-c`, which always quits. The binding is therefore dead and draws no warning. Change: in `KeySpec::is_ctrl_c`, compare the character case-insensitively (`matches!(self.code, Key::Char('c' | 'C'))`) so these spellings are rejected with the existing "Ctrl-c always quits" warning.
3. [nit] `drop_chord_prefix_singles` can leave a user-set action with no keys. For example, `top = "g g"` with `bottom = "g"` drops `g` from `bottom`, and `bottom` ends up unbound rather than keeping its default `G / End`. This matches the planner note ("dropped with a warning"), but the resulting warning does not say that the action is now unbound. Change (optional): add "; it is now unbound" to the warning in `drop_chord_prefix_singles` (and to the same-context collision warning in `apply_override`) when the action's key list becomes empty.
4. [nit] `Keymap::from_config` logs each warning with `log::warn!` and also returns them. If the caller logs returned `ConfigWarning`s the way it does for config warnings, each keymap warning will be logged twice. Change: either drop the `log::warn!` loop in `from_config` and leave logging to the caller, or document that the returned warnings are already logged.
