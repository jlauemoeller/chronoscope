## Findings
1. [nit] Real `advisor_tool_result` blocks carry `content: {"type":"advisor_redacted_result","encrypted_content":"..."}` (every instance in local transcripts). `result_text` in `src/harness/claude/wire.rs` has no `text` field to use here, so it falls back to the object's compact JSON. The stored "output" is then the encrypted blob, often over 4 KiB and so lazy. In the same way, `web_search_tool_result` content (an array of objects without `text`) flattens to an empty string. Pairing and status are correct, and no AC defines this text. Change: in `result_text` (or in `attach_result`), treat `*_redacted_result` content as empty/redacted output rather than JSON. Optionally render web-search results as `title — url` lines. Then change `server_tool_result_in_an_assistant_line_becomes_the_result` in `tests/claude_assembly.rs` to use the real redacted shape (the test currently uses an invented `advisor_result`+`text` shape). Task 019 (tool body renderers) can take this if preferred.
2. [nit] If a turn's first message has model `<synthetic>` (or no model), `AssistantTurn.model` becomes `"<synthetic>"`/`""`, and the first real message then emits a `ModelChange`. That contradicts the build notes' rule that `<synthetic>` never produces a note. Change: in `on_assistant` (`src/harness/claude/assemble.rs`), when the current `turn.model` is empty or `<synthetic>` and a real model arrives, set `turn.model` to it without inserting a `ModelChange`. Add a test.
3. [nit] Current transcripts contain `user` entries with no `origin`, no `isMeta` and no `tool_result` (28 in a sample of 30 local sessions, next to 168 `origin: human` prompts). The older-format fallback in `on_user` applies regardless of version, so these become User turns and split Assistant turns. This follows SPEC §5.1 rule 1 as written. Task 007 does not explicitly claim these entries (they are probably interrupt markers or local-command output). Change: record this in task 007's scope (or a follow-up), so it checks what these entries are and narrows the fallback if needed.
4. [nit] SPEC §9.1/§9.6 describe adapter fixtures as "trimmed copies of real sessions", but the only Claude fixture is hand-written. The planner notes allow this for this task, but it is why findings 1 and 3 slipped through. Change: when task 007 or 009 adds fixtures, include a scrubbed real excerpt with a redacted advisor call and an origin-less user entry.
