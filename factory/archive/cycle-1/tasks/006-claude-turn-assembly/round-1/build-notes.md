Design decisions to note:
- Block index for text/thinking ids and replacement is `apiBlockIndex + position in the line's content array`; without `apiBlockIndex` it is just the position in the line (documented in a test). Real transcripts carry `apiBlockIndex`, so two adjacent redacted thinking blocks stay two items.
- `<synthetic>` model messages never produce a `ModelChange`; the note is generated by comparing with the previous message's model (so A, B, A gives two notes). Item id of the note is `model:<message.id>`.
- Tool-result matching works for `tool_result` in `user` lines and any `*_tool_result` block (e.g. `advisor_tool_result`) in `assistant` lines; `api-request-blob` and all other types are ignored by dispatching on the top-level `type`.
- A tool result for a call is only attached to a known call (results before their call are dropped). An Assistant turn is only created by an `assistant` line.
- `tokens` = latest `input_tokens + output_tokens` per distinct `message.id`, summed; `None` if no usage seen. It is kept current if more messages arrive after `turn_duration`.
- Deferred to task 007 as the planner notes say: `queued_command` attachments (spec rule 1) and other attachments, injected/`isMeta` content, compaction, parse-warning counting. Malformed lines are silently skipped.
- Fixture is hand-written (no scrubbing needed), see `tests/fixtures/README.md`.
