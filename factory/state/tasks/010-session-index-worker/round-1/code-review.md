## Summary
The index worker, stats cache, harness registry and `is_active` are well structured: idiomatic, no panics on user input, clean shutdown, and thorough integration tests over real fixture copies. The test gate passes. One bug blocks: whenever the index has more than one harness, rescheduling stats for one harness throws away the waiting stats jobs of every other harness, so "Stats arrive for every session" does not hold. The remaining findings are nits.

## Findings
1. [must-fix] `src/index/worker.rs:431` (`Coordinator::schedule_stats`, the `self.queue.replace_with(..)` call) — The closure removes *every* waiting job from `pending` and the queue, whichever harness it belongs to, and installs only harness `i`'s `wanted`. `main_loop` builds the harnesses back to back, so `build(1)` discards harness 0's queued jobs. Only the ones a pool thread already took (at most 3) survive. Those sessions get no `Stats` until harness 0 rebuilds itself. A harness with a live session rebuilds every 500 ms and can starve the other harness's stats for good. `SessionIndex::start` takes a `Vec` of harnesses and `prune()` is written for several, so this is this task's contract, not task 028's. Change: in the closure, drop and un-pend only old jobs with `job.harness == i`, and keep the other harnesses' waiting jobs (and their `pending` entries) in the queue ahead of or merged with `wanted`, keeping newest-first order within each harness. Add a test in `tests/index.rs` with two harnesses. Use a stub `Harness` whose `stats()` is slow (e.g. sleeps or blocks on a barrier), and give harness 0 more sessions than `MAX_STATS_THREADS`, so its queue can't drain before `build(1)` runs. Assert that every session of both harnesses gets a `Stats` event.
2. [nit] `src/index/worker.rs` `Coordinator::record` — A stats job for an older key that finishes after the job for the current key still sends its `Stats` and overwrites `sent`. The UI then shows the older stats until the next snapshot. Two jobs for the same session can run at once on a growing file, so the window is narrow but real. Change: still insert into the cache, but send the event only when `done.key` is in `self.harnesses[done.harness].live_keys`. Optional (perf): don't queue a session that already has a job running, and re-queue it when that job finishes. This avoids several concurrent full parses of the same large, growing transcript.
3. [nit] `src/index/worker.rs` `schedule_stats`, `self.sent.retain(|(h, id), _| *h != i || sessions.values().flatten().any(|s| &s.id == id))` — This is O(sessions²) on every rebuild, which means every 500 ms while a session is live. Change: build a `HashSet<&SessionId>` of the snapshot's ids once and retain against it.
4. [nit] `src/index/worker.rs:471` `Coordinator::prune` — `self.harnesses.iter().any(|h| h.live_keys.is_none())` is vacuously false when no harness is constructed. Starting with Claude disabled (or, later, with any harness disabled) therefore prunes that harness's cache entries and saves the emptied file. Change: prune only keys owned by harnesses that ran (e.g. keep entries whose `stats_key` prefix belongs to a harness that is not constructed), or skip pruning when `harnesses` is empty.
5. [nit] `src/index/cache.rs` `StatsCache::write` — The temp file has a fixed name, `stats-v1.json.tmp`. Two concurrent instances (e.g. two tmux panes) can interleave their writes and rename a mixed file into place. The next load treats it as corrupt, so nothing is lost but the cache. Change: use a unique temp name in the cache dir (e.g. `tempfile::NamedTempFile::new_in(&self.dir)` + `persist`, or a pid suffix).
6. [nit] `src/harness/mod.rs` `build_harnesses` — When home detection fails, `map_or_else(PathBuf::new, ..)` gives an empty home. The default Claude data dir then silently becomes `./.claude/projects`, resolved against the cwd. Change: log a warning when `Paths::detect()` returns `None` (or skip the default-dir harness and keep it unavailable), so the fallback is visible.
7. [nit] `src/harness/claude/assemble.rs` `first_timestamp` / `last_timestamp` docs — "the first/last entry the assembler read that has one" is not quite accurate. `timestamp()` is only called for user/assistant entries, the handled `system` subtypes and injected attachments. Noise entries with timestamps are not counted, so `SessionStats::duration` spans conversation entries only. Change: say so in both doc comments (and in the `Harness::stats` doc for Claude).
8. [nit] `tests/index.rs` `dropping_the_handle_stops_the_worker_and_disconnects_the_receiver` — The comment says "The watcher is gone too: changes cause nothing", but the test makes no change after the drop. Change: either append to a fixture after the disconnect and assert nothing more arrives (or the handle reports finished), or reword the comment to what is asserted (the cache file exists).
9. [nit] `tests/index.rs` `a_missing_data_dir_gives_an_unavailable_snapshot_and_is_polled` — The last step ("Once the directory exists it is watched") also passes through polling, because `poll` is 100 ms and the appended file gives a different snapshot. Change: reword the comment, or check that the harness is watched (e.g. a fresh index with a long `poll` over the now-existing dir that reacts to a change within the coalesce window).
