## Findings
1. [nit] `Prompt`, text longer than the prompt, any width: the scroll is recomputed from the cursor alone on each draw ("the least that shows the cursor cell"). So on `←` from the end of a long text, the cursor stays pinned at the right edge and the window slides left on every press until the start of the text is visible. Only then does the cursor travel across the field. It works and the cursor is always visible, so the planner rule is met. Many line editors instead keep the scroll offset and move the cursor inside the window until it reaches an edge. Change (optional): keep a scroll offset in `Prompt`, and change it in `visible_text` only when the cursor cell would fall outside `[offset, offset + width)`. Seen in the scratch crate with `Prompt` alone at width 16: `←` from cursor 40 to 28 on a 40-char text keeps the cursor at col 15.
