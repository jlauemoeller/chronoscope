## Findings

[nit] `a_stale_result_after_a_revert_to_the_sent_key_is_dropped` (`tests/index_stub.rs:339`) failed in my first full `cargo test`, then passed in the next full run and in five further runs of that binary. Change: open a follow-up to remove the race in the test.
2. [nit] No test notices if `go_to_turn` stops ending a search's temporary unfolding: with `self.settle_temp_unfold()` removed from `go_to_turn` in `src/components/transcript/paging.rs`, the whole library suite still passed. The code is right today, since it is the same epilogue as `perform`. Change: add a test to `src/components/transcript/tests/go_to_turn.rs` that temporarily unfolds a section through a search, calls `GO_TO_TURN_ATTR` for another turn, and asserts the same fold state as `]` gives.
3. [nit] `a_turn_that_arrives_while_the_sidebar_has_focus_adds_a_row_and_moves_nothing` covers only a transcript away from the end. When it is following, a probe showed the transcript does move (offset 87 to 92, its selection on the new turn) and the sidebar stays on its entry, with a row added. That matches the follow rule the spec keeps (§6.4, base §7.2), but no test pins it, and the criterion's wording has no such exception. Change: add a test in `src/app/browser_tests/sidebar_keys.rs` for `G`, focus the sidebar, then append a turn, asserting the row is added, the sidebar's entry is unchanged and the transcript still follows.
4. [nit] `SPEC.md` §6.4 and the comment at `src/components/turn_block/section.rs:193` give "only an HTML comment" as text that renders no rows, but a probe confirmed the build notes: `<!-- x -->` renders a row and has a selectable section. The code path is the generic one and the tests use a link reference definition, which does render nothing, so behaviour is fine. Change: correct the example in the comment, and let the spec's owner decide whether to correct the spec's example or make the renderer drop HTML comments.
5. [nit] The test name `the_selector_hidden_and_back_wide_does_not_give_the_sidebar_the_focus_back` (`src/app/browser_tests/sidebar_keys.rs:879`) says "selector", but the test opens the help overlay. Change: rename it to `an_overlay_hidden_and_back_wide_does_not_give_the_sidebar_the_focus_back`.
