## Findings
1. [must-fix] Moving the selection in the Sessions pane never requests a redraw. `App::session_selected` (`src/app/selector.rs`, around lines 303–307) only sets `self.selector.session`. It calls neither `set_attr` nor `request_redraw`. `run_loop` draws only when `take_redraw()` returns something other than `None`, and `Tick` redraws only when the active flags change. So in the running app, j/k/↑/↓ in Sessions move the `SessionList` cursor internally, but the `>` marker, the band and the scroll stay stale on screen until some unrelated change arrives (a stats event, a focus move, an activity flip). Moves in Projects are not affected, because `push_sessions`/`push_cwd` go through `set_attr`, which marks the screen dirty. Change: in `session_selected`, once the id is accepted and differs from the current selection, set it and call `self.request_redraw(RedrawRequest::Dirty)`. Also add an update test to `src/app/selector_tests.rs`: `loaded()`, `focus_sessions(&mut app)`, `app.take_redraw()`, `press(&mut app, Key::Char('j'))`, then `assert_eq!(app.take_redraw(), RedrawRequest::Dirty)`. A matching assertion for a Projects move would guard the other pane too.
2. [nit] Two state-4 snapshots duplicate existing ones. `the_active_marker_in_an_unselected_row_120x40_styled` renders exactly `startup_120x40_styled`. `the_active_marker_inside_the_band_120x40_styled` renders exactly `sessions_focused_120x40_styled` (and `sessions_focused_theme_default`). Change: drop the duplicates and note in a comment that state 4 is covered by the startup and sessions-focused styled snapshots (and the cell checks in `the_active_dot_is_primary_outside_the_band_and_inverted_inside_it`). Alternatively, give state 4 its own fixture, for example with the active session in a non-first row.
3. [nit] If a live `Snapshot` reports the harness currently shown with `available: false`, `snapshot` → `keep_selection` keeps it as `current`, and `push_tabs` still draws it as the selected `primary` tab. That contradicts "unavailable tabs are muted and can't be selected" (§6.6). No acceptance criterion covers it. Change (optional): when the current harness becomes unavailable, switch to `first_available()` (or show nothing), and add a test.
4. [nit] `row_parts` in `src/components/session_list.rs` mixes `GAP.len()` (bytes) with display widths. It is correct for the ASCII gap, but `GAP.width()` would state the intent.
