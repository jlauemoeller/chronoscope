## Findings
1. [must-fix] A number outside the `f64` range inside `message.usage` (Claude) or `tokens` (OpenCode) now fails the whole line or row, although the same data parses on `main`. This breaks the binding planner note "A wire field added by this task must not turn a line or row that parses today into an unparsed one", and the §9.5 rule that changed harness data degrades rather than fails. The cause is that `lenient` and `lenient_object` in `src/harness/shared.rs` first call `Value::deserialize`, which rejects such a number with `number out of range`. `lenient_object` wraps the whole object, so fields the app never reads are affected too. The value is unrealistic, but the regression is real and costs the whole line's content, not only a token figure. I ran the real `Assembler`s from this branch and from `main`:

   | Input | `main` `unparsed_count` | Branch `unparsed_count` |
   |---|---|---|
   | Claude `usage: {"output_tokens":7,"cache_read_input_tokens":1e400}` | 0 | 1 |
   | Claude `usage: {"output_tokens":7,"server_tool_use":{"web_search_requests":1e400}}` | 0 | 1 |
   | OpenCode `tokens: {"output":7,"cache":{"read":1e400}}` | 0 | 1 |
   | OpenCode `tokens: {"output":7,"unknown":1e400}` | 0 | 1 |

   Change: make `lenient` and `lenient_object` stop going through `serde_json::Value`, so that an out-of-range number in a new or unread field no longer fails the line or row. One way that I checked in a standalone probe, using copies of the helpers and of a reduced `Usage` struct: enable serde_json's `raw_value` feature in `Cargo.toml`, deserialize a `Box<serde_json::value::RawValue>`, then return `serde_json::from_str::<T>(raw.get()).ok()`, and in `lenient_object` keep the object check by testing that `raw.get()` starts with `{`. In that probe, both `1e400` Claude inputs above parse, with the known field kept and the out-of-range field `None`, and the wrong-type, array and `null` cases behave as they do now.

   Add tests on each harness, in `tests/claude_assembly.rs` and in `replace_tests` in `src/harness/opencode/assemble.rs`. Each test feeds `1e400` in a new field (`cache_read_input_tokens` / `cache.read`) and in an unknown field nested in `usage` / `tokens`, and asserts `unparsed_count() == 0`, that the text item is kept, and that the out-of-range field counts as zero.
