## Changes
- `src/components/transcript/follow.rs` (new) and `mod.rs`, `updates.rs`: the `Transcript` has `following`, `loading`, `new_sections` and `tail_from`. Following is decided from the prepared window (no extra layouts) after every `Cmd` (`perform` wraps the old body as `run`), on viewport changes, and on `Loaded`. `Appended`/`Updated` pin the view to the last row while following (the selection moves to the new last section if it was on the last one); otherwise offset and selection are kept and the sections that arrive (new turns, and new sections in the last turn from the moment the user left the end) are counted. `Loaded` ends loading and evaluates following; `Reset` starts loading again. New builder `loading(bool)`, getters `following()` / `new_sections()`, query attrs `NEW_SECTIONS_ATTR` / `FOLLOWING_ATTR`. A key that changes the count answers the new `Msg::NewSections(n)`. A resize while following keeps the view at the end. In-place updates reuse the existing offset adjustment for blocks above the viewport; new: when the selected section lies entirely above the top row inside the block that straddles it, the offset moves by that section's height change (`selected_above_top_row` / `keep_screen_for` in `updates.rs`).
- `src/app/selector.rs`: `push_viewports` reads the transcript's count back after announcing the viewport, so a resize that shows the end again (which resumes following) clears a stale `↓ N new`.
- `src/app/mod.rs`, `src/app/browser.rs`: new `Msg::NewSections`; `BrowserState` keeps the load progress, the new count, the latest `Activity` and the live flag. `Loaded` is forwarded to the transcript; after each forwarded update the app reads the transcript's count. Help-line status items are built by `refresh_status` (`Loading… N%`, then `↓ N new`). `Activity` is stored; `refresh_live` (on `Activity` and on every `Tick`) applies `is_active_at` with the injected clock and pushes `LIVE_ATTR` to the header only when the value changes. Every accepted session update marks the screen dirty. The transcript is mounted with `loading(true)`.
- `src/model/mod.rs`: `is_active_at` (the §7.2 rule on bare values), used by `is_active`.
- `src/components/browser_header.rs`, `components/mod.rs`: `LIVE_ATTR`, `live(bool)`; `● live` right-aligned on the cwd row ending at column `w - 3` (`●` primary, `live` muted_foreground), the parse-warning note two cells to its left; the cwd is cut to leave room.
- Tests: `components/transcript/tests/follow.rs`, header tests, `app/browser_tests/live.rs` (+ `Rig` gets an injectable clock), six new snapshots under `src/app/browser_tests/snapshots/`.
