## Findings
1. [must-fix] `doc/SPEC.md` §9.5 (line 843) adds "Every field that is read is optional, and a field of an unexpected JSON type counts as missing instead of failing its line". This is false as built and contradicts cycle 2 §3 ("a known field of the wrong JSON type fails the whole line") and the header of `src/harness/claude/wire.rs`. I ran the assemblers from a scratch crate. Each of these variants gives `unparsed_count() == 1` and loses the turn: Claude `message.model: 5`, `message.id: 5`, `timestamp: 5`, `cwd: 5`, `durationMs: "x"`; OpenCode `cost: "x"`, `time: "x"`. §3.1 (line 152) points at §9.5 with "Every one of these fields is optional, and a field of an unexpected type counts as missing". Change: scope both sentences by reader, not by field. In §9.5, keep "every field is optional", then state: (a) while assembling, a value of the wrong type counts as missing for Claude `message.usage` and its counts, `message.stop_reason`, both `isApiErrorMessage` and `toolUseResult` / `isAsync`, and for OpenCode `tokens`, `finish` and `error`; (b) the details overlay's re-read tolerates a wrong type in every field it reads, and a bad value only drops its row; (c) a wrong type in any other field the assembler reads (`timestamp`, `message.id`, `message.model`, `cwd`, `durationMs`, OpenCode `time`, `cost` and so on) fails that line or row, which is then skipped and counted like a malformed line. In §3.1 line 152, keep the sentence but say it applies to the overlay's re-read, and refer to §9.5 for assembly.
