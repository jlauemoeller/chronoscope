## Findings
1. [nit] `src/components/transcript/tests/keys.rs`, `the_screen_row_is_kept_only_when_the_end_of_the_transcript_allows_it`: the assertion `t.offset() <= total - 24` always holds because `refresh` clamps the offset, so the test can't fail. Change: after `G` then `+`, assert that the view is still at the end (`t.offset() == total_height(&mut t) - 24`) and that the selected last section is still on screen. Or delete the test, since `fold_all_keeps_the_selected_sections_screen_row` already covers the anchor.
2. [nit] `src/components/transcript/paging.rs` `select_in_view`: a selected section taller than the viewport is never "fully visible". So `PgDn`/`Ctrl-d` while reading it moves the selection to any short section that becomes fully visible below, even though the tall section still fills most of the screen. This follows the binding planner rule ("no longer fully visible") literally. SPEC §6.3 says "when the current one leaves the viewport", which arguably allows keeping it. No change is required. If the Approver prefers the SPEC reading, also keep the selection when the selected section still covers the viewport's top row, and add a test for that case.
3. [nit] `src/components/transcript/paging.rs` `turn_stop`: `]`/`[` select the block's first non-system section rather than literally "the first section of the block" (planner note). This is a deliberate reading of AC2 ("never stop on system content"), and it is documented in the doc comment and build notes. The block's top border still lands at the top. Change: none needed. This is flagged only so the Approver sees the interpretation.
