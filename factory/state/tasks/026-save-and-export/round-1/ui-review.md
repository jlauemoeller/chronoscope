## Findings
1. [nit] `Saved to …` / `Exported to …` toast, long absolute path, any size (e.g. 80x24). The toast caps at `MAX_TOAST_WIDTH` and cuts the text at its end. With a long typed path the file name disappears: `Exported to /home/user/Documents/exports/a-rather-long-…`. The UI section ties toasts to the task-012 style, so this is not a contradiction. Change: when building the success toast text, cut the path at its start with `…` (the same `tail_fitting` rule `Prompt::confirm` uses) so it fits `MAX_TOAST_WIDTH - TOAST_CHROME` minus the `Saved to ` / `Exported to ` prefix. The toast would then read `Exported to …-project-name-20261021-0835-85a86657.md`. See `ui/exported-toast-long-path-80x24.txt`.
2. [nit] Path prompt (`Save to: ` / `Export to: `) when the pre-filled or typed path is wider than the row. At 60 columns this happens once the sanitised project name is longer than about 18 characters. The prompt scrolls horizontally to keep the cursor visible and drops the start of the path without a `…` marker. This behaviour comes from the existing `Prompt` (shared with search) and is not new in this task. Change (optional, could be a follow-up): when the visible text does not start at column 0 of the input, draw `…` in the first text cell.
