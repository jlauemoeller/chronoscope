## Findings
1. [nit] "The margin" has two meanings here, and the code's docs claim one it does not implement. SPEC §6.2 calls the place two cells before the border the right margin, and the acceptance criteria say a press on the margin does nothing, yet `turn_at` returns the entry for columns 1, 2, 27 and 28 of its row, and `a_click_selects_the_row_wherever_in_the_row_it_lands` asserts this. The build notes read "the margin" as the `SidebarGap` column plus the border. I did not make this a must-fix because the goal says "like the selector's lists", the planner's wording echoes the doc of `row_at` in `src/components/list_pane.rs`, and `row_at` has the same column check, with a test that selects at column 18 of a 20-wide pane (`row_at_maps_a_cell_to_the_row_drawn_there`). Change: in `src/components/turn_sidebar/mod.rs`, remove "the margin" from the `turn_at` doc (line 210) and the module doc (line 42), or state that the blank cells of an entry's row belong to the row. `turn_at` never sees the gap column, so the current wording is untrue on either reading.
2. [nit] The app-level "bottom border" dead spot misses the pane. In `dead_spots()` (`src/app/browser_tests/sidebar_mouse.rs:332`), `("bottom border", 10, 29)` on `compaction_rig` (120 x 30, pane height 23, starting at screen row 5) presses screen row 34, below the screen. The component test `a_press_elsewhere_in_the_pane_answers_nothing` does cover the bottom border, so the criterion holds. Change: use pane row 22.
3. [nit] After the wheel moves onto an entry with nothing selectable, a click on the transcript that leaves its selection where it was does not sync the sidebar. A probe in a scratch copy (turns `u0`, hidden, `a0` at 120 x 40, transcript focused, one wheel step down, then a press on each of transcript rows 0 to 5) left the sidebar on entry 1 and the transcript's selection on `u0` every time. The sidebar keeping its row after the wheel is the planner's decision, and the next change of selection heals it, so this is narrow, but §6.3 says the selected row is the turn of the transcript's selected section. The test meant for this case hides it: `a_click_on_the_transcript_after_the_wheel_moved_the_sidebar_on_syncs_it` (`sidebar_mouse.rs:649`) uses `click_entry`, not the wheel, so the sidebar has the focus and the sync always pushes. Change: rename the test to say it starts from a click. Then either accept the state or make a press on the transcript force a push (set `sidebar_section` to `SidebarSection::NotPushed`) and add a test that uses the wheel.
4. [nit] `a_double_click_does_what_enter_does` (`sidebar_mouse.rs:224`) lands on `a1`, which has one section, so "first selectable section" is trivially true there. Comparing the `Presentation` with `j` x3 and `Enter` makes the test adequate, since both use `go_to_turn`. Change: optionally add a double-click on a turn with several sections, asserting the selection is on the first.
5. [nit] `with_an_overlay_open_the_sidebar_gets_no_mouse` (`sidebar_mouse.rs:715`) does not open `Id::DetailsOverlay`, which `OVERLAYS` also lists, and its `area` binding exists only for `assert!(area.width > 0)` at line 746, which proves nothing. Change: add the details overlay to the array and remove `area` and that assertion.
