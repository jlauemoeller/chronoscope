## Findings
1. [nit] `src/theme/builtin.rs` `dim`: the doc says this is "ratcn's `dim`", but it only blends `Rgb`/`Rgb` pairs. ratcn resolves named colours through a VGA approximation (`resolve_rgb`) and clamps `amount` to 100. Here, `amount > 100` would underflow `100 - amount` and panic in debug builds. All current calls give the same results as ratcn, so nothing is wrong today. Change: either clamp `amount` (`let amount = amount.min(100);`) and say in the doc comment that named colours pass through unchanged (unlike ratcn), or add a `debug_assert!(amount <= 100)`.
2. [nit] `src/theme/parse.rs` `color_from`: bare TOML integers are accepted as indices (`accent = 99`). This goes beyond the planner-note format, though it doesn't contradict it. Change: none needed. Consider mentioning it in the module doc's format block so the user-theme task documents it consistently.
3. [nit] `src/theme/mod.rs` `TokenOverride` / `Theme::with_token`: the public `bg` and `modifiers` fields let code give a background or modifiers to any token, e.g. `user_title`. The planner note says tokens are fg-only except `search_match` and `toast`. TOML parsing never produces this, so it is an API looseness, not wrong behaviour. Change (optional): make the fields private and expose constructors that only allow `bg` for `SearchMatch`/`Toast`. Alternatively, document that `bg`/`modifiers` are intended only for those tokens and for `without_colors()`.
