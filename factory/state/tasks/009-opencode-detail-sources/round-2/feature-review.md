## Findings
1. [must-fix] `find_part` (`src/harness/opencode/details.rs:219-238`) can read `start` from a part the assembler did not use, which breaks the planner note that `start` has "the same source as the duration". It takes the first match and ignores the part's `type`, while the assembler (`part_item`, `upsert`) makes tool calls only from `type: "tool"` parts and lets the last part with an id win. All three cases below were confirmed by throwaway tests:
   - Two tool parts `c1` in one row (1 s at 22:13:21, 5 s at 22:21:40) show `start 22:13:21` with `duration 5s`.
   - A `reasoning` part with the id `c1` before tool part `c1` shows `start 2020-09-13 12:26:40`, the reasoning part's time.
   - A tool part without an id, found by `<row id>:<index>`, whose position now holds a `reasoning` part shows that part's time as `start`, with no `unavailable`, although the tool part is gone.

   Change: add `#[serde(default, rename = "type", deserialize_with = "lenient")] kind: Option<String>` to `PartHead`. In `find_part`, keep only parts with `kind == Some("tool")`, replace `.find(...)` with `.filter(...)` using the same predicate, and take `.last()`. With this change in the throwaway copy, all 194 tests matching `details` passed, and the cases gave `start 22:21:40`, `start 22:13:21` and `duration`, `status`, `unavailable`. Add a test to `details_tests.rs` for each case, asserting those values.
2. [nit] With `finish: "error"`, the `error` row depends on the shape of a useless `error`: `{}`, `""` and `{"type":5,"message":true}` show `error  error`, while `12` and an absent `error` show no row. Each is defensible, since the first group matches the notice and the second counts as missing. Only `{}` is pinned, in `the_error_row_says_what_the_notice_of_the_same_row_says` (`details_tests.rs:531`). Change: add `r#""error":{"type":5,"message":true}"#` to that list so the decision is pinned.
3. [nit] `Rows::text` (`src/harness/opencode/details.rs:252-258`) only drops empty strings, so a whitespace-only `agent`, `model.providerID`, `finish`, `rawFinish` or `snapshot.start` shows a label with a blank value (confirmed by a throwaway test). The error parts are already trimmed. Change: filter on `!v.trim().is_empty()`.
4. [nit] Still open from round 1, and declared in the build notes: `reading_details_leaves_the_database_untouched` runs only in rollback-journal mode, while spec/SPEC.md §3.2 says the real database uses WAL. Change: add a WAL variant that asserts the database file's bytes are unchanged.
