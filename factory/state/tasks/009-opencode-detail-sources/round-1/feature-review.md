## Findings
1. [must-fix] A tool part that a later row sends again leaves the reference on the first row, so the overlay mixes two parts. `upsert` (`src/harness/opencode/assemble.rs:846`) replaces the item but keeps its source entry. The assembler already treats a later row re-sending a known id as a case to handle (`a_row_pushed_after_a_removed_notice_replaces_the_item_it_names_not_a_shifted_one`, `notice_tests.rs`). Confirmed with `c1` in rows `a1` (1 s) and `a2` (5 s, about 8 minutes later): the Tool call group shows `start` from `a1` and `duration` `5s` from `a2`, and Environment shows `a1`'s snapshot. The planner note requires `start` to have "the same source as the duration". Change: add a `TurnSources` method that sets the row of an existing item's entry, and call it from the replace branch of `upsert` so that the reference follows the row the item now comes from. Resolve the row the way `note_item` does, by sharing that logic: `flush_current` calls `upsert` with an empty `row`, and an injected item takes its row from the `injected:` prefix, so the raw `row` argument must not be written. Add a test in `details_tests.rs` with the same part id in two rows, asserting that `start` and `snapshot.start` come from the later row. `a_row_replaced_in_place_keeps_the_references_of_a_fresh_assembly` must still pass.
2. [must-fix] An `error` with no usable part gets an invented row. `message_group` (`src/harness/opencode/details.rs:149`) calls `error_text` for any `RowError`, and its fallback is the text `error`. Confirmed: `"error":{"type":5,"message":[1]}`, `"error":{}` and `"error":""` on a `finish: "stop"` row each show `error  error`, with no notice on that row. The first breaks "a value of an unexpected JSON type is left out" (acceptance criterion and planner note); the others break "missing fields are left out" (§5.3). Change: in `message_group`, add the row only when `type` or `message` is a non-empty string after trimming, using a small `RowError` method in `assemble.rs`, and leave the notice's fallback as it is. A row with `finish: "error"` and an absent `error` already has a notice and no row, so this case becomes consistent with it. In `details_tests.rs`, remove `"error":{}` from `the_error_row_says_what_the_notice_of_the_same_row_says` (line 526) and add a test that these three values give no `error` row and no `unavailable`.
3. [must-fix] A `content` part that is not an object makes the Tool call group `unavailable`, although the row parses and the tool part is intact. `ToolHead.content` is `Option<Vec<PartHead>>` (`src/harness/opencode/details.rs:300`), so one odd sibling fails the whole list, while the assembler reads the same row with `Vec<Value>` and shows the call. Confirmed with `"content":["odd",{...tool c1...}]`: the group shows `duration`, `status`, `unavailable`, and the valid `start` is lost. The planner note limits `unavailable` to database gone, row deleted or `data` not parseable, and asks for tolerant heads. The build notes record this behaviour as a decision, and no test covers it. Change: read `content` as `Option<Vec<Box<RawValue>>>` in `find_part`, parse only elements starting with `{` as `PartHead`, and skip the others while keeping their index, because `<row id>:<index>` depends on it. Add a test with a non-object sibling, for a part with an id and a part found by position, asserting `start`, `duration`, `status` and no `unavailable`.
4. [nit] `reading_details_leaves_the_database_untouched` (`src/harness/opencode/details_tests.rs:775`) only runs in rollback-journal mode (`TempDb::new`), while spec/SPEC.md §3.2 says the real database uses WAL. In a throwaway WAL run the database file's bytes stayed the same, but `opencode.db-shm` and `opencode.db-wal` appeared when they did not exist before. That comes from opening with `Db::open`, not from this task's code, and the acceptance criterion is about the file's bytes. Change: add a WAL variant that asserts the bytes are unchanged, and raise the leftover files separately if they matter.
5. [nit] `a_tool_call_and_its_result_share_one_reference` (`src/harness/opencode/details_tests.rs:311-312`) ends by asserting `text.lines().is_none()` on the text section, under a comment about the tool call's result. Change: make that assertion on the tool call's reference.
6. [nit] `a_table_of_lines_has_no_row_references` (`src/model/sources.rs`) uses an empty table with no lines. Change: add a line entry with `add_line` and assert that `get` gives `SectionRefs::Lines`, or rename the test.
7. [nit] `read_groups` (`src/harness/opencode/details.rs:49-55`) reads and parses the row twice when the section's row is the turn's first row, and `find_part` parses `data` a third time. This is off the hot path (one overlay open). Change: reuse the row when `turn_row == section.row`, if the code stays simple.
