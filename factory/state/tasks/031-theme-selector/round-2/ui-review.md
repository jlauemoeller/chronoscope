## Findings
1. [must-fix] ThemeSelector, invalid user theme with a long id, 60x20 (any size where `id + " (invalid)"` is wider than the label space) — `ThemeRows::line` truncates the whole label, so ` (invalid)` is cut off. With a 45-column id at 60x20, the row reads `catppuccin-mocha-custom-high-contrast-v2-test (i…`. At 60x20 the label gets 49 columns, so any id of about 39 columns or more loses the suffix. The suffix is the only thing that tells an invalid row from a valid one: both are `muted_foreground`. Without it, a broken theme looks like a valid one that the cursor skips for no visible reason. That contradicts the task's `UI` section ("Invalid user themes are `my-theme (invalid)` in `muted_foreground`") and §8.4. The new test `a_label_wider_than_the_overlay_is_cut_with_an_ellipsis` asserts the bad output (`│    an-extremely-long-invalid-theme-i… │`). Before this round the label was clipped at the border, and the suffix was lost the same way. Round 1's nit 3 asked for ellipsis truncation but didn't say the suffix must survive, so this follows from that suggestion and is not the Builder's misreading.

   Change: for invalid items, truncate only the id, to `width − 5 − " (invalid)".width()` columns, and always append ` (invalid)`. For example, keep `id` and an `invalid` flag on `ThemeItem` and build the row text in `ThemeRows::line`, instead of storing the preformatted label. The 60x20 row should then read `│    catppuccin-mocha-custom-high-contrast-… (invalid) │`. Update the test's expected row to end in `… (invalid) │`. Add a 60x20 text snapshot of a long invalid id. See `ui/theme-selector-long-invalid-id-60x20.txt`.
2. [nit] Scrolled-list snapshot, 60x20 — unchanged from round 1 nit 2. The task text says "12 themes at 60x20", but under the binding height rule `min(h − 2, rows + 5)`, 12 themes fit at 60x20, so the Builder used 16. No code change is needed. The planner may want to fix the task text.
