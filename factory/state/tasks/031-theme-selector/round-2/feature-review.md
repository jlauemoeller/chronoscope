## Findings
1. [must-fix] `src/components/theme_selector/rows.rs` `ThemeRows::line` (and `ThemeItem::invalid`): the new `truncate_with_ellipsis(&item.label, …)` cuts the whole label. For an invalid theme, that label is `"<id> (invalid)"`, so a long id loses the ` (invalid)` suffix. The test `a_label_wider_than_the_overlay_is_cut_with_an_ellipsis` in `src/components/theme_selector/mod.rs` asserts exactly that row: `│    an-extremely-long-invalid-theme-i… │`. §8.4 says a theme that fails to parse "is listed muted with `(invalid)`", and the first acceptance criterion requires `<id> (invalid)`. Under `NO_COLOR`, muted has no colour, so the truncated row looks just like a valid theme, and the user loses their only in-app sign that the theme is broken. Change: keep the id and the suffix apart. Either store a separate `invalid: bool` and build the row text at render time, or truncate only the id. Cut the id to `width − ROW_CHROME − width(" (invalid)")` columns with `truncate_with_ellipsis`, then append ` (invalid)`. Then change the `rows[4]` assertion so the row ends in `… (invalid) │`, for example `│    an-extremely-long-invalid-… (invalid) │`.
2. [nit] This is carried over from round 1. The acceptance criterion and UI state 5 say "12 themes at 60x20", which contradicts the binding height rule `min(h − 2, rows + 5)`: 12 themes need 17 rows, and 60x20 allows 18, so the list does not scroll. The builder's boundary test and the 16-theme snapshot meet the intent. Change: none in the code. The planner should correct the task text, for example to "16 themes at 60x20".
3. [nit] `src/components/theme_selector/mod.rs` `move_cursor` (around line 147): if there is only one selectable theme, with invalid themes both before and after it, the leading invalid rows are scrolled into view but the trailing ones can stay hidden. The second `select(Some(0))` overrides the first `select(Some(last))`. This is a rare corner case and the cursor is always visible. Change (optional): when the cursor's index is both the first and the last selectable row, prefer showing the trailing run, or skip the reveal when both runs cannot fit.
4. [nit] `src/config/edit.rs` `insert_line`: the line ending of the new `theme` line is taken from the file's first line, not from the line where it is inserted. In a mixed-ending file, the new line can end differently from its neighbours. Every byte of the original text is still kept, so this is cosmetic only. Change (optional): take the ending from the line just before `at`, if there is one.
5. [nit] `src/config/edit.rs` `with_theme`: the planner note says to use `toml_edit::DocumentMut`. A missing key is now added by inserting a line into the raw text, located through the spans of the parsed `toml_edit::Document`. `DocumentMut` is used only when a non-value `theme` is replaced. This is still driven by `toml_edit`, keeps the original bytes better than the planner's approach would, and is what the round-1 code review suggested. It is noted only so the Approver knows about the deviation. Change: none.
