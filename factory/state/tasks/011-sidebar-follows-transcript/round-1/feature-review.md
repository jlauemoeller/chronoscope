## Findings
1. [must-fix] `the_sidebar_does_not_follow_while_it_has_the_focus` (`src/app/browser_tests/sidebar_follow.rs:502-528`) does not test the focus check. After `]` the transcript is not at the end, so the append never moves its section, and the only-on-change guard alone prevents the push. With `sidebar_follows` changed to always return `true`, all of `sidebar_follow::` still passes, so nothing guards this binding planner note, and task 012 would extend an unguarded check. Change: rewrite the test so the transcript's section really moves while the sidebar has the focus: press `G` and settle so the transcript is following, record `section(&rig.app)`, call `active(&Id::TurnSidebar)`, set `SELECTED_ATTR` to `selected_value(Some(2))`, `update` with `session_msg(.., ModelUpdate::Appended(vec![arc(reply("late", "Late."))]))`, then assert `section` changed and `sidebar_entry` is still `Some(2)`. I ran this version in a scratch copy: it passes on the branch and fails with `left: Some(8), right: Some(2)` under the mutation.
2. [nit] Going back to a parent whose covered, following transcript moved onto a turn without an entry leaves the sidebar with no selection and the offset at 0 (probe: entry `Some(8)` before opening the subagent, `None` after going back). `push_sidebar_rows` drops the selection with the old rows, and the no-entry rule then has nothing to keep. The spec and planner notes do not define this combination, though it sits awkwardly with "does not clear and does not jump". Change, if wanted: remember the parent's selected turn on the `Level` when opening a subagent, and set it through `SELECTED_TURN_ATTR` after the rows in `close_subagent`, before the sync.
