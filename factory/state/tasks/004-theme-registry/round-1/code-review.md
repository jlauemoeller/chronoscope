## Findings
1. [must-fix] `src/theme/resolve.rs`, test `colorterm_and_no_color_are_parsed_from_the_environment_in_one_place` (end of `mod tests`). `after.find("\n    }\n").unwrap()` only matches LF line endings. `.github/workflows/ci.yml` runs `cargo test` on `windows-latest`, and the repo has no `.gitattributes`. Git on the Windows runners defaults to `core.autocrlf=true`, so `include_str!("resolve.rs")` will contain `\r\n`, `find` returns `None`, and the test panics. That breaks the required CI gate (SPEC §9.3). Change: normalise line endings before scanning, e.g. `let production = include_str!("resolve.rs").replace("\r\n", "\n");` and then split on `#[cfg(test)]` as now. Alternatively, find the end of `from_env` without relying on newlines. Adding a `.gitattributes` with `* text=auto eol=lf` would also work, but it changes repo-wide behaviour, so the in-test fix is preferred.
2. [nit] `src/theme/resolve.rs`, `resolve_by_id`. `.unwrap_or_else(|| ThemeError::Syntax(String::new()))` cannot be reached, and it makes up an error. Change: match on the entry variant directly (`Some(ThemeEntry::Valid { theme, .. }) => Ok(...)`, `Some(ThemeEntry::Invalid { error, .. }) => Err(ResolveError::Invalid { id, error: error.clone() })`, `None => Err(ResolveError::Unknown(..))`), so the dead fallback goes away.
3. [nit] `src/theme/resolve.rs`, `resolve` (NO_COLOR branch) and `adapt`. `resolve` passes `builtin::default_theme()` into `adapt` only as a placeholder, and `adapt` replaces it via `builtin::get(TERMINAL_ID).unwrap_or(theme)`. That hides intent, and a missing Terminal built-in would silently colour-strip Default instead. Change: add a small helper such as `fn no_color_theme() -> Theme` that builds the Terminal built-in, use it explicitly in the NO_COLOR paths, and have `adapt` only apply the transforms.
4. [nit] `src/theme/registry.rs`, `read_user_themes` / `with_user_themes`. The extension match ignores case, and Linux filesystems are case-sensitive. So `foo.toml` and `foo.TOML` both give id `foo`. The stable sort keeps `read_dir` order, which depends on the filesystem, so which file wins is not deterministic. Change: sort by `(id, path)`, or dedupe explicitly, and log a `warn!` for the ignored duplicate.
5. [nit] `src/theme/registry.rs`, test `user_themes_are_appended_alphabetically_by_id`. On this btrfs machine `read_dir` returns files in creation order (zeta, then alpha), so the test catches a missing sort here. On other filesystems (ext4 hash order, tmpfs) it may pass even without the sort. Change: add a unit test that calls `with_user_themes` with input in reverse order and checks that the result is sorted.
6. [nit] `src/theme/resolve.rs` uses `config::DEFAULT_THEME`, and `src/theme/builtin.rs` defines `DEFAULT_ID`. Both are `"default"`. Change: use one constant, e.g. make `config::DEFAULT_THEME` an alias of `builtin::DEFAULT_ID` or use `builtin::DEFAULT_ID` in `resolve.rs`.
7. [nit] `src/theme/registry.rs`, `read_user_themes`. An I/O read failure is wrapped as `ThemeError::Syntax("could not read file: …")`, which displays as "invalid theme TOML: could not read file: …". That is misleading in the log and in later UI. Change: add a `ThemeError::Io(String)` variant (or similar), or accept the wording knowingly.
8. [nit] `src/theme/registry.rs`, `with_user_themes`. The sort is by byte order, so `Zeta` sorts before `alpha`. If "alphabetically" (§8.4) is meant to ignore case, sort by a case-folded key with the id as tie-breaker. This does not block.
