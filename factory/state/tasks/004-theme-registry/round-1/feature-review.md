## Findings
1. [nit] In the `NO_COLOR` branch, `resolve` (`src/theme/resolve.rs`) passes `builtin::default_theme()` into `adapt`, and `adapt` then swaps it for the Terminal theme. The result is correct, but the code reads as if the default theme were involved. Change: in that branch, pass `builtin::get(builtin::TERMINAL_ID)` (or a small `builtin::terminal_theme()` helper) directly. The `unwrap_or(theme)` fallback inside `adapt` can then be simplified.
2. [nit] Under `NO_COLOR`, `adapt` always uses the built-in Terminal theme, even when the user has a valid `terminal.toml` replacing it. Colours are reset either way, so only the name and the theme's own `transparent_background` can differ. That fits the planner note's wording ("the `terminal` theme"), but it is undocumented. Change: add one line to the doc comment on `adapt`/`resolve` saying the built-in Terminal theme is used deliberately.
3. [nit] `read_user_themes` (`src/theme/registry.rs`) reports a file read failure as `ThemeError::Syntax("could not read file: …")`. That labels an I/O failure as a syntax error. Change (optional): add an I/O variant to the error, or leave as is and document it.
4. [nit] The extension check accepts `.TOML` as well as `.toml`, case-insensitively. On a case-sensitive filesystem, `x.toml` and `x.TOML` both give id `x`. Because of the in-place replacement, whichever file `read_dir` returns later replaces the earlier one, and the stable sort keeps the input order for equal ids, so the result depends on `read_dir` order. Change: match `.toml` exactly, as the spec's `*.toml` says, or break ties by full file name.
5. [nit] The env-read tests scan the source text for `env::var`. That catches the obvious cases but is brittle, for example against a `use std::env::var;` import. This is acceptable as a guard; no change required.
6. [nit] In `resolve_by_id` (`src/theme/resolve.rs`), `.unwrap_or_else(|| ThemeError::Syntax(String::new()))` can never run. An entry without a theme is always `Invalid`, so `error()` is always `Some`, and the fallback would invent an empty error if it ever did run. Change: match on `ThemeEntry::Valid { theme, .. }` / `ThemeEntry::Invalid { error, .. }` directly instead of calling `theme()` and then `error()`.
7. [nit] `with_user_themes` (`src/theme/registry.rs`) sorts with `String::cmp`, which is case-sensitive byte order, so `Zeta.toml` sorts before `alpha.toml`. The spec does not pin the collation down. Change (optional): sort case-insensitively, then break ties by the raw id.
8. [nit] Under `NO_COLOR`, `resolve` gives no warning for an unknown or invalid configured id. The planner note's "with no warning" covers this, and the build notes document it. If the warning is wanted later, it can be added without changing the theme returned. No change required now.
