## Findings
1. [nit] `TurnSidebar::paint_background` (`src/components/turn_sidebar/mod.rs:206-214`) paints one column beyond the area it is given, and the component imports `crate::app::layout::SIDEBAR_GAP` to do it. This stretches the "a component draws only itself" rule of spec/SPEC.md §1.3. It is not a must-fix: the criteria require `hit_test` to find nothing in the gap, `App::view` may not draw, and `every_cell_of_the_browser_is_painted_with_the_background` needs the column painted, while `SelectorFrame` already paints outside its own area and no visible behaviour is wrong. Change: document on `BrowserAreas::sidebar` in `src/app/layout.rs` that the sidebar also paints the gap column's background, or pass the gap to the component as a prop so it does not depend on the layout module.
2. [nit] The widest-duration snapshots show less than their names say. `widest_durations_90x24_*` has no selection and a 13-row list, so it ends at `59m 59s`. `the_widest_duration_selected_in_the_focused_pane` (`src/components/turn_sidebar/snapshots.rs:156`) selects entry 9, `26h 30m` (7 cells), not an 8-cell duration, so no snapshot has an 8-cell duration inside the band, and `9999h 0m` never appears at 90x24. Change: use `.with_selected(Some(11))` there, which selects `9999h 0m`, and re-accept those four snapshots after reviewing them.
3. [nit] `the_background_is_painted_over_the_pane_and_the_gap_unless_transparent` (`src/components/turn_sidebar/tests.rs:737`) never exercises the transparent case, and `a_transparent_theme_leaves_the_browser_unpainted` checks no cell in the pane or the gap. Change: add an assertion to the test that with `builtin::default_theme().with_transparent_background(true)` the cells `(15, 10)` and `(30, 10)` keep `Color::Reset` as background.
4. [nit] `thinking_alone_is_not_a_section` (`src/components/turn_sidebar/tests.rs:936-950`) is named for the opposite of what it asserts, and it would pass whatever thinking does, because `with_stats` gives the turn a footer section and so an entry. Change: rename it `readable_thinking_is_a_section`, remove the `with_stats` wrapper, and add `assert_eq!(entry_for(&redacted_only("a1")), None)`.
5. [nit] `the_rows_of_the_transcript_and_the_sidebar_agree_after_a_live_session` (`src/app/browser_tests/sidebar.rs:338`) sends no live update, so it only compares the rows after the initial load. Change: send an `Appended` new turn, an `Appended` known id and an `Updated` through `session_msg` before comparing, which is what its name promises.
6. [nit] Some test text is stale or loose. In `src/components/turn_sidebar/tests.rs:770-773`, the comment names `a0` while the code inserts `x0`, and the `updated(vec![user("u1")])` and `rows.apply(&ModelUpdate::Loaded)` lines do nothing. At `tests.rs:879`, the `contains('>') || contains("Compaction")` check would also pass on an unrelated row. In `src/app/browser_tests/sidebar.rs:46`, the doc comment of `pane_rows` mentions `from` and `to`, which do not exist. Change: remove the no-op lines, correct the comment and the doc comment, and assert at `tests.rs:879` that row 18 has `>` in column 3.
