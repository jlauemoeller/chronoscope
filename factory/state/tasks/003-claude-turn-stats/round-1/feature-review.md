## Findings
1. [must-fix] Ineffective test for a required behaviour: no test protects the dirty marking for a count change. The planner notes require that the count is updated in `on_assistant` and "the turn is marked dirty so that an `Updated` is sent". Removing `changed = true` from that stats refresh (`src/harness/claude/assemble.rs:886`) leaves the whole suite passing, because the late messages in the tests carry text and `upsert` marks the turn dirty anyway. With that line removed, a late message that adds no item (for example `"content":[]`) updates the count without sending `Updated`; a scratch test confirmed this, and it passes on the current code. Change: in `tests/claude_assembly.rs`, add a test next to `a_message_after_a_footer_updates_the_count` that pushes the first three of `late_message_lines()`, then `{"type":"assistant","uuid":"a-m2","timestamp":"2026-01-01T00:00:06Z","message":{"id":"m2","model":"x","content":[]}}`, and asserts `[ModelUpdate::Updated(t)]` with `message_count` 2. No change to `assemble.rs` is needed.
2. [must-fix] Missing test for a required behaviour: no test covers a compaction without a boundary ending the association with the prompt. The planner notes require that "a compaction ends the association with the prompt", and `on_compact_summary` treats a summary without a boundary as a compaction. Removing `self.prompt_ts = None` from that branch (`src/harness/claude/assemble.rs:659`) leaves the whole suite passing; `a_compaction_ends_the_association_with_the_prompt` only goes through `on_compact_boundary`. Without that line, the duration would run from the prompt across the compaction. A scratch test passes on the current code. Change: in `tests/claude_assembly.rs`, add a test with `human("2026-01-01T00:00:00Z")`, `COMPACT_SUMMARY`, `reply("m1", "2026-01-01T00:10:00Z", "x")` and `footer(Some("2026-01-01T00:10:30Z"), Some(1000), "7")`, asserting a duration of 30 s. No change to `assemble.rs` is needed.
