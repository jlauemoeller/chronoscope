## Findings
1. [must-fix] Distinct text blocks of a flagged message on separate lines without `apiBlockIndex` overwrite each other, so all but the last are lost from the error. `src/harness/claude/assemble.rs:837` keys `error_text` by `api_index.unwrap_or(0) + i`, which is 0 for every such line, so the "by block number" comment on `Builder.error_text` does not hold. Flagged lines `first` then `second` of one message give the notice text `second`; the planner note requires the text blocks joined with newlines (`first\nsecond`), and base spec §3.1 says one line per content block. With `apiBlockIndex` 0 and 1 the result is correct, and the ordinary text path without an index gives two `Item::Text` items. The one flagged line in the local transcripts has no `apiBlockIndex`, so this is the path such lines take. Change: without `apiBlockIndex`, number the blocks as `block_id` does: treat a block as a re-send (replace) only when its text starts with the message's most recent error block, otherwise give it the next number. Add a test to `tests/claude_notices.rs` asserting `first\nsecond` for those two lines, and keep the identical-repeat test passing.
2. [must-fix] A flag arriving after the same text has already become `Item::Text` does not replace that block, so the error is shown twice. The flag is sticky only for later lines (`assemble.rs:809-812`), and the `Some("text") if api_error` arm at line 830 never touches earlier items. An unflagged `API Error` line followed by a flagged `API Error` line of the same message gives `[Text("API Error"), Notice(Error, "API Error")]`, contradicting §4.2 "**replacing** its text block so it isn't shown twice" and the acceptance criterion on duplicates. Change: when a flagged line's notice text is computed, delete with the `remove` helper any earlier `Item::Text` of that message whose text equals the error text or is a prefix of it, so positions stay right for later tool results. Leave other earlier text blocks alone, so real assistant text is not folded into the notice. Add tests in `tests/claude_notices.rs` for the sequence above, asserting one `Error` notice and no `Item::Text`, and for a `tool_result` attaching to a call that follows the removed text.
3. [nit] `src/harness/claude/assemble.rs:726` treats `stop_reason: ""` as missing, which goes beyond the spec's "null" rule and has no test. Suppressing `stopped: ` is reasonable; add a one-line comment or a test so it is deliberate.
4. [nit] The stop-reason state lives in the per-turn `Builder`, so "last non-null value per message id" stops at a human prompt: `max_tokens`, a prompt, then `end_turn` on the same message id leaves the warning in the first turn. Text blocks already split the same way across turns and this input is very unlikely, so no change is needed beyond noting it in the `stop` field's comment.
