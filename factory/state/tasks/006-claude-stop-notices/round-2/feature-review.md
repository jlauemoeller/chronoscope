## Findings
1. [must-fix] No test covers the `Builder.index` fix-up in `remove` (`src/harness/claude/assemble.rs`, the `for at in b.index.values_mut()` loop). The planner's removal trap names `Builder.index` as a position store that a removal shifts, and base spec §5.1 rule 3 requires a repeated block to replace its earlier version, including after a removal. In a scratch copy with that loop disabled, every test tracked in the repo still passes. With the same change, a tool call sent again after a removed notice panics in `upsert` (`index out of bounds: the len is 2 but the index is 2`), and a text sent again after `take_message_text` is added as a second block (`hello` and `hello world`) instead of replacing the first. The current code gets both right; the tests would not catch a regression. Change: add two tests to `tests/claude_notices.rs`:
   - Lines `line(1, "msg_1", r#""max_tokens""#, &text("One"))`, `line(2, "msg_1", "null", &tool_use("c1"))`, `line(3, "msg_1", r#""end_turn""#, "")`, `line(4, "msg_1", "null", &tool_use("c1"))`, `result_line(5, "c1")`. Expect no notice, exactly two items (the text and the call), and the call's status `Ok`.
   - Lines `line(1, "msg_e", "null", &text("err"))`, `line(2, "msg_1", "null", &tool_use("c1"))`, `line(3, "msg_1", "null", &text("hello"))`, `api_error_line(4, "msg_e", "null", "err")`, `line(5, "msg_1", "null", &text("hello world"))`, `result_line(6, "c1")`. Expect `texts(&items) == ["hello world"]`, one `Error` notice with `err`, and the call's status `Ok`.
2. [must-fix] A removal can leave two `Item::Injected` next to each other, breaking base spec §5.1 and §5.6 ("Consecutive injected entries collapse into one section with a count"). Each `Item::Injected` renders as its own section (`src/components/turn_block/section.rs`), so the reader sees two `1 injected item` sections instead of one `2 injected items`. Confirmed by probe, with a meta entry being a `user` line with `isMeta: true`:
   - Text of `z`, meta, `m` with `max_tokens` and no blocks, meta, `m` with `end_turn` and no blocks gives `[Text, Injected(1), Injected(1)]`.
   - Text of `z`, meta, text of `m`, meta, a flagged `m` line gives `[Text, Injected(1), Injected(1), Notice]`.

   `flush_current` keeps this rule for entries that arrive next to an `Injected` item, but `remove`, new in this task, can create the same adjacency afterwards. Change: in `remove` in `src/harness/claude/assemble.rs`, after `turn.items.remove(pos)`, when `pos > 0` and the items at `pos - 1` and `pos` are both `Item::Injected`, extend the first with the second's entries and take the second out through the same position renewal (`b.index` and `calls`), dropping its id from `b.index`. The merged item keeps the first id, as `take_held` does. Add tests to `tests/claude_notices.rs` for both sequences above, expecting one `Injected` with 2 entries, and a `tool_result` for a call after the merged item still attaching.
