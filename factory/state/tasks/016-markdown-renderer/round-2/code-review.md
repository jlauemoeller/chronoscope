But the intersection happens before layout, so when an area overhangs the right edge of the buffer, the text is re-wrapped at the visible width instead of `area.width`. `the_widget_clips_to_the_buffer_instead_of_panicking` asserts this: a 20-wide area wraps "wide text here" at 4 cells. This only happens when an area overhangs its buffer; a full frame buffer starting at 0,0 with in-frame areas never hits it. Change (optional): lay out at the original `area.width`, and clip only when drawing (skip rows outside `buf.area`, and limit each `set_line` to the part inside `buf.area`). Then update the test to expect "wide" truncated on row 0.

A probe in a scratch copy confirmed this. `| a | b |\n|---|---|\n| | |\n| c | d |` renders `["a │ b", "──┼──", "", "c │ d"]`, and an empty header row renders `["", "──┼──", "c │ d"]`. Inside a table that looks like the blank line between blocks. Change: when no cell is non-empty, keep every column, e.g. `.map_or(widths.len(), |i| i + 1)`, so the row still shows its separators.
