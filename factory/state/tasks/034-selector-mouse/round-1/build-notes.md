## Changes
- `src/app/mouse.rs` (new): the router. `hit_test(&ScreenLayout, col, row)` is a pure function that returns the topmost component and its area; components under the topmost overlay (selector frame, help, theme selector) are never candidates. `RoutedMouse` is the event a component receives (position relative to its area, plus the area size). `MouseState` holds the cached routing layout, the last press and the injected click clock. The `App` handlers for `Msg::Mouse`, project clicks and session clicks are in the same file.
- Routing design: `GlobalEvents` has one mouse subscription over the whole screen, only when `mouse = true`, and turns left presses and wheel steps without modifiers into `Msg::Mouse`. tuirealm 4.1 forwards a mouse clause on position alone (kind and modifiers are not compared), so the filtering is in `GlobalEvents::on`. Per-component area subscriptions were rejected: `Application::unsubscribe` removes every subscription of the component and of the same clause, so refreshing them would break the table; and the focused component gets every raw `Event::Mouse` in screen coordinates anyway.
- `App::update(Msg::Mouse)` hit-tests against `App.mouse.routing` and calls the component's `on` with `Event::User(UserEvent::Mouse(RoutedMouse))`. A distinct event is used because the focused component also receives the raw `Event::Mouse` in screen coordinates; lists and tabs ignore the raw one. The returned `Msg` is applied with `update`.
- Routing areas (`ScreenLayout` from the same pure `layout()` that `view` uses) are recomputed by `App::refresh_routing`, called at the end of every `update`, from `resized`, `push_viewports` (screen changes) and `show_toast_for`. `view` never touches it. `ScreenLayout` now derives `Default`.
- `src/app/selector.rs`: new `SelectorMsg::{ProjectClicked, SessionClicked, PaneClicked, ListScrolled}`. Clicks focus first, then select (in the filtered selector `focus_pane(Projects)` ends the filter, which resets the project). `session_selected` now also returns early (redraw only) when search results are listed, because the list owns its cursor over results.
- Components: `ProjectList`, `SessionList` and `HarnessTabs` turn `RoutedMouse` into `Msg`s. `PaneState::row_at` maps a cell to the row drawn there (border, blank row, margin and area under the last row are not rows). `ListCursor::scroll` scrolls the viewport without selecting.
- Double-click: `MouseState::press` (400 ms inclusive, same project row or same session row, forgotten after it fires). Time comes from `App::set_click_clock` (an injected `Instant` clock, separate from the `DateTime` clock behind the active marker). Session double-click queues `Msg::OpenSession` with `emit`; project double-click focuses Sessions (like `Enter`).
- `mouse = false`: `GlobalEvents::subscriptions(keymap, mouse)` adds no mouse subscription, and `App::mouse` also returns early (defence in depth).

Decisions beyond the task text:
- A click in the empty area of the Sessions pane uses the normal `focus_pane`, so with no selection the newest session is selected (SPEC §4.1 invariant that a focused Sessions pane has a selection); the project is untouched.
- Prompts: with the search prompt open only the Sessions pane takes the mouse (click selects a result and the double-click opens it, wheel moves the result selection; the prompt keeps the input); Projects and tabs are ignored. Any other prompt (resume confirmation) makes the selector ignore the mouse.
- Help overlay and theme selector: everything under them is ignored; "click outside closes it" is task 035. The browser under the selector overlay and the browser alone take no mouse yet (035).
