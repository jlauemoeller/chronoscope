## Findings
1. [nit] `src/components/transcript/window.rs` (`Window::build_clamped`), used by `refresh_scrolled` in `mod.rs`. The second half of round-1 nit 1 is still open. When the requested offset needs clamping, the first `build` takes every reused layout out of the `Measurer`'s `reuse` map (`HashMap::remove`), and the window it built is then dropped. The second `build` at the clamped offset lays out every visible block again. So each `Cmd::Scroll(Down)` at the bottom of the transcript returns `NoChange` but still re-runs `TurnBlock::layout` for the whole window, which is the per-tick cost the reuse was meant to remove. Change: in `build_clamped`, clamp first with `cache.clamp_offset(offset, height, measurer)`, then build once. Alternatively, when a rebuild is needed, add a `Measurer` method (in `content.rs`, since `reuse` is private) that returns the first window's layouts (`window.into_layouts()`) to the reuse map before the second `build`. Add a counter assertion to `scrolling_lays_out_only_the_newly_exposed_blocks`: one extra `scroll_down` at the bottom leaves `layouts_run` unchanged.
2. [nit] `src/components/transcript/mod.rs` (`measured_reusing`). The signature spells out `std::collections::HashMap<usize, crate::components::turn_block::BlockLayout>` inline, which is the same style round-1 nit 6 fixed in `updates.rs`. The body also duplicates `measured`. Change: import `HashMap` and `BlockLayout` with `use` at the top of the module, and implement `measured` as `self.measured_reusing(HashMap::new(), f)` (or the other way round) so there is a single body.
3. [nit] `src/components/transcript/tests.rs` (`scrolling_lays_out_only_the_newly_exposed_blocks`). `let mut exposed = 0;` followed by a single `exposed += …` is a mutable variable that is only assigned once. Change: write `let exposed = t.visible_blocks().end - visible.end;`.
4. [nit] `src/components/transcript/updates.rs` (`restore_selection`). Only the "nearest following section" path calls `reveal_selection`. The two early returns do not: `ensure_selection` when nothing was selected, and `first_section_from(0)` when the selected turn is no longer indexed. The first case is harmless at offset 0. But if the user has scrolled down a transcript whose earlier blocks have no selectable sections, a selection created by a later batch can land off screen. Change: call `self.reveal_selection()` in those two branches as well, after the selection is set (or restructure so that every path that changes `content.selected` ends in the one reveal).
