2. [nit] The `trim_end` in the `Notice` arm of `section_text` (`src/transcript_search.rs`, line 285) has no test: removing it in a scratch copy leaves all notice tests passing. Change: extend `a_notice_is_searched_by_its_text` in `src/transcript_search/tests.rs` with a notice whose text ends in `\n\n`, and assert that `section_text` returns the text without it.
3. [nit] `emphasized_lines` (`src/components/turn_block/export.rs`, line 142) escapes `_` and `*` but not `\` or a backtick. This comes from reading the code against CommonMark's rules; I did not render it. A message containing `` `foo_bar` `` exports as `` _`foo\_bar`_ ``, and the backslash shows literally because a code span does not process escapes. A message containing `a\_b` exports as `a\\_b`, which leaves the `_` unescaped and can break the emphasis. A line indented by four or more spaces after a blank line becomes an indented code block, so its `_` delimiters show literally. No text is lost from the file. Change: escape `\` first, then `` ` ``, `_` and `*`; cap the indent written outside the emphasis at three spaces; and add these cases to `an_exported_notice_keeps_its_indent_outside_the_emphasis_and_escapes_markers`.
4. [nit] `trailing_whitespace_of_a_notice_draws_no_extra_marked_row` (`src/components/transcript/tests/notice.rs`, line 326) tries `t.select(&error()) || t.select(&item_section("a1", "n1"))`, but `error()` is that same id. Change: use `assert!(t.select(&error()))`.
