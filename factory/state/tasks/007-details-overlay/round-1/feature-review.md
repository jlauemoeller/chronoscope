## Findings
1. [must-fix] A `details` key bound to a chord opens the overlay but cannot close it. This breaks SPEC.md §5.1 ("The `details` key also closes it") and the remapped-key criterion. Chords are valid in the browser context (spec/SPEC.md §8.5, `Context::supports_chords`). The transcript opens on them through `KeyResolver`, but `DetailsOverlay::on` (`src/components/details_overlay/mod.rs:140-142`) uses `Keymap::resolve`, which handles single keys only. In a probe with `details = ["x i"]`, which loads with no warnings, the transcript answered `Msg::OpenDetails`, while the overlay answered `None` to both `x` and `i`. Change:
   - Add a `KeyResolver::new(Context::Browser)` field to `DetailsOverlay`, as its presentation state.
   - In the `FrameKey::Unbound` arm, feed the key to it. `Resolved::Action(Action::Details)` gives `Msg::CloseDetails`; anything else gives `None`.
   - Call `reset()` on the resolver when an overlay-context key is handled, so a stale prefix cannot complete later.
   - Add a component test with `"x i"` in `details_overlay/mod.rs`: `x` gives `None`, then `i` gives `Some(Msg::CloseDetails)`.
   - Add an app-level test in `src/app/browser_tests/details.rs` that opens and closes the overlay with the chord.
2. [nit] The wanted size is fixed when the overlay opens (`src/app/details.rs:37`; the build notes call this deliberate). If the terminal is widened, the overlay stays narrow and values stay wrapped even with room to spare. If it is narrowed, the overlay can show `↓ more` with vertical room left. Scrolling still reaches every row, so nothing is hidden. It will matter more once tasks 008 and 009 add `cwd`-style values. Change: recompute the wanted size on resize, for example by having the `App` keep the content's size inputs or asking the component for its desired size at the new width.
3. [nit] `interior_from_value` (`src/components/overlay_frame.rs:233-236`, re-exported at `src/components/mod.rs:48`) is never called, although its doc says it is for tests and the `App`. Change: remove it and the re-export.
4. [nit] `copy_save_and_export_do_nothing_while_it_is_open` (`src/app/browser_tests/details.rs:476`) presses `Ctrl-w`, which is a global quit key, not the second save key. `Ctrl-s` is never pressed. Change: use `(Key::Char('s'), KeyModifiers::CONTROL)`.
5. [nit] The "wheel outside is ignored" check in `the_wheel_scrolls_the_overlay_and_a_press_outside_closes_it` (`src/app/browser_tests/details.rs:623`) uses (0, 0), which is the browser header, so it does not show that a transcript cell outside the overlay gets nothing. `nothing_under_the_overlay_gets_the_mouse` only uses points inside the overlay. Change: also send a wheel step at a transcript cell outside the overlay and assert that `presentation` is unchanged.
6. [nit] `SCREEN_MARGIN` (`src/app/details.rs:18`) and the literal `4` in `src/components/details_overlay/snapshots.rs:225` repeat the margin hard-coded in `help_overlay_rect` (`src/app/layout.rs:300`). Change: share one constant from `layout.rs`.
7. [nit] Some doc comments edited in place now run past the wrap width: the `layout` doc in `src/app/layout.rs`, the `outside_overlay` doc in `src/app/mouse.rs:218`, `key_clause` in `src/components/global_events.rs`, and `open_theme_selector` in `src/app/theme_selector.rs`. Change: rewrap them.
