[nit] `src/components/details_overlay/content.rs:259-269` (`char_wrap`) — When a value ends in a space and the cut falls on that space, the unconditional `pieces.push(current)` after the loop adds an empty piece. Probe results: `char_wrap("abcd ", 4)` gives `["abcd", ""]`, and a row `abcdefgh ` draws a blank continuation row, which is the same "reads as a group gap" effect that round-1 ui-review 4 removed for trailing newlines. It is not reachable with this task's model rows, but tasks 008 and 009 pass raw harness strings. Change: after the loop, push `current` only if it is non-empty or `pieces` is empty, and add this case to `a_space_the_cut_falls_on_does_not_start_the_next_row`.
2. [nit] `src/components/details_overlay/mod.rs:161-176` — A chord whose second key is an overlay key opens the overlay but does not close it. In a probe with `details = "z j"`, `z` `j` opens, and `z` `j` again scrolls and leaves it open; `Esc` still closes it. This does not block and is not a repeat of round 1's must-fix: it follows the binding planner note that `Context::Overlay` is resolved first, and the existing test `the_overlay_keys_come_first` already accepts the single-key version, where with `details = "j"` the `j` key scrolls and does not close. A chord whose first key is an overlay key (`j i`) gave a keymap warning at load in the probe, so only the second key is affected. Change, if wanted: when `self.resolver.is_pending()`, feed the key to the resolver before `self.frame.on_key`, and answer `Msg::CloseDetails` on `Resolved::Action(Action::Details)`, so that a started chord can complete.
3. [nit] `src/components/details_overlay/content.rs:133-143` (`widest_row`) — It measures the raw value with `split('\n')`, while `layout` draws `display_lines`, so the width is measured on different text than is shown. `UnicodeWidthStr` counts a control character as one column, so in a probe a 50-column value ending in `\r` wanted 62 columns instead of 61, and one ending in three `\u{1b}` wanted 64. It never wraps too early, so the cost is only spare columns. Change: map over `display_lines(&row.value)` in `widest_row`, and measure control characters the same way `char_wrap` does, for example by summing `UnicodeWidthChar::width(ch).unwrap_or(0)`.
4. [nit] `src/app/details.rs:35-37,43-44` — `open_details` works out `wanted` with `desired_size`, stores it, and `refresh_details_size` immediately replaces it with the same value. Change: set `details_size` to a placeholder only as the "open" marker, or pass the max width to `DetailsOverlay::new` and drop one of the two computations, so there is one path to the size.
