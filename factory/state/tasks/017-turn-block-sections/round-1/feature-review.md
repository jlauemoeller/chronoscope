## Findings
1. [nit] A folded prompt can get an unstyled ellipsis. In `src/components/turn_block/sections/mod.rs`, `ellipsize` takes the `…` style from the last span, and falls back to `Style::default()` when the line has no spans. In a folded prompt whose second rendered line is the blank line of a paragraph break (e.g. `"Fix it.\n\nLog: …"`), the result is `▶ Fix it.` / `  …`, with the `…` in Reset instead of `foreground` whenever it is not dimmed. Change: give `ellipsize` a fallback-style parameter, or have `UserPromptSection::lines` (`sections/user.rs`) style the ellipsis with `ctx.foreground()`. Add a folded test for a two-paragraph prompt.
2. [nit] Folded thinking shows raw markdown. `sections/thinking.rs` builds the folded row with `first_line(self.0)` on the raw text, so `**bold**` or backticks in the first line show literally. Unfolded thinking and the folded prompt both use rendered markdown, and §5.5 says thinking is rendered as markdown. Change: take the first non-blank line of `render_markdown(self.0, …)` output instead of `first_line` on the raw text.
3. [nit] The unfolded tool description is char-wrapped. `sections/tool.rs` `ToolCallSection::description` uses `char_wrap` when unfolded. The description is prose, and §5.5 says prose is word-wrapped (char-wrap is for commands and tool output). Change: word-wrap the description, and keep `char_wrap` for the input JSON and the result.
