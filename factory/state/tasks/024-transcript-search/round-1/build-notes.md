## Decisions worth knowing
- `attr` cannot answer a `Msg`, so "the Transcript replies with `StartTranscriptSearch`" is realised as: App sets the query attr, queries the request payload (query + corpus + generation) from the transcript (same pattern as `NEW_SECTIONS_ATTR`) and emits `Msg::StartTranscriptSearch` itself.
- AC "if the user pressed Enter (fold toggle) on it in between, it stays unfolded": implemented as stated. While a section is only *temporarily* unfolded, `Enter` (and `unfold`) make the unfolding explicit (the section stays unfolded when the selection leaves); a second `Enter` is the normal toggle and folds it. `fold` on it folds it explicitly; fold-all/unfold-all settle everything. Tests: `enter_on_the_unfolded_section_makes_the_unfolding_explicit`, `unfold_and_fold_commands_also_end_the_temporary_state`.
- Matches are a snapshot of the search: turns that arrive later (live append) are not searched until `/` is used again; a `Reset` clears the search.
- Highlight is applied to every visible rendered row (folded rows too, e.g. a folded tool description); a match split across a wrap boundary is not highlighted (looked for per row).
- The row to scroll to is the k-th occurrence of the query in the section's rendered rows (k = the match's index within its section); if rendering hides it (markdown syntax, truncation) the section is revealed instead; a match counted beyond the rendered occurrences of a truncated tool output expands the output temporarily.
