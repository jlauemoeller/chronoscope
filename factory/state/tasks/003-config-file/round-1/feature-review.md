## Summary
Config loading, `Paths`, the file logger and `TimestampFormatter` are all implemented. Every acceptance criterion traces to a test that would fail if the behaviour broke, and fmt, clippy and test all pass (78 tests). One behaviour bug remains. `is_valid_format` only checks chrono's parse-time `Item::Error`, so a `timestamp_format` that chrono tokenises but cannot render (e.g. `%#z`) is accepted with no warning, and every timestamp then renders as an empty string. That breaks the binding planner rule that a format chrono rejects falls back to the default with a warning.

## Findings
1. [must-fix] Formats that chrono cannot render pass validation, so timestamps go blank with no warning. `src/timestamp.rs` `is_valid_format` (line 12) only looks for `Item::Error` while parsing. I checked against chrono 0.4.45 (the version in `Cargo.lock`): `"%Y %#z"` tokenises without `Item::Error`, so `is_valid_format` returns true, but `write!(s, "{}", dt.format_with_items(..))` returns `Err(fmt::Error)` with an empty string. This happens for both `DateTime<Utc>` and `DateTime<FixedOffset>`. As a result:
   - `Config::from_table` (`src/config/mod.rs` line 201) accepts the value with no warning.
   - `TimestampFormatter::new` keeps it.
   - `render` silently returns `""` for every timestamp. Its comment says "The format was validated, so writing cannot fail", which is false.

   This breaks the binding planner rule that "a `timestamp_format` that chrono rejects" falls back to its default with a warning.

   Change: make `is_valid_format` also render a fixed instant and require success. For example, keep the `Item::Error` check and add: `let t = FixedOffset::east_opt(0).unwrap().with_ymd_and_hms(2026, 1, 1, 0, 0, 0).unwrap(); let mut s = String::new(); write!(s, "{}", t.format_with_items(StrftimeItems::new(format))).is_ok()`. Using `FixedOffset` covers both the UTC and fixed or local render paths. Then add tests:
   - in `src/timestamp.rs`: `assert!(!is_valid_format("%#z"))`, and `TimestampFormatter::new("%#z", false, plus_two())` falls back to the default rendering;
   - in `src/config/tests.rs`: `timestamp_format = "%Y %#z"` gives the default plus one warning keyed `timestamp_format`.
2. [nit] The `src/paths.rs` tests use literal paths (`/tmp/cfg`, `/tmp/cache`, ...) instead of temp directories, while the AC wording says "unit tests with temp directories". I accept this because `from_dirs` is pure and never touches the filesystem, and nothing mutates the environment, so the AC's intent (deterministic, no env mutation) is met. Optionally use `tempfile::tempdir()` paths to match the wording literally.
3. [nit] `format_short` still shows seconds for composite specifiers. `src/timestamp.rs` `short_format` only handles `%S`, fractional specifiers and `%T`, so `%X`, `%r`, `%c`, `%+` and `%s` keep their seconds (e.g. `%X` renders `08:35:15`). The planner rules don't list these specifiers. Either expand `%r` to `%I:%M %p`, `%X` to `%H:%M`, and so on, or document the limitation in the `short_format` doc comment.
4. [nit] `tests/logging_append.rs` holds two tests in one binary, although its header says "Own test binary". `init_logging_failure_is_an_error_not_a_panic` would also pass if a logger were already installed, because `set_boxed_logger` would then return an error. So the test proves less than its name says. There is no race today, because `create_dir_all` fails before the logger is installed. Change: move the test to its own `tests/` file, or assert that the error kind is not the "logger already set" error (e.g. that `err.kind() != io::ErrorKind::Other`).
5. [nit] Config warnings are lost if config loads before logging starts. `Config::load` and `from_toml_str` send their warnings to `log::warn!`, which drops them if `init_logging` hasn't run yet. Add a sentence to the `Config::load` doc comment saying the caller should call `init_logging` first so the warnings reach the log file. This guides the later wiring task.
