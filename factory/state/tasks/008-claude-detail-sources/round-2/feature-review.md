## Findings
1. [must-fix] The rule that the Message group prefers a message's latest line with a non-null `stop_reason` over a later line has no test at assembler level. The planner notes bind this ("the message's latest line with a non-null `stop_reason`, or else its latest line"), and §4.2 gives the same rule. In a scratch copy I changed `src/harness/claude/assemble.rs:862` to `.note_message_line(message_no, range, false)`, so no line ever counts as stopped, and all of `cargo test` still passes. Every existing test has the stopped line last, and `a_message_item_gets_the_latest_stopped_line_else_the_latest` in `src/model/sources.rs` tests only the table, not what the assembler passes it. The code is correct today: a probe with lines null, `end_turn`, null shows `stop_reason=end_turn` with the second line's timestamp and branch. Change: add a test to `tests/claude_details.rs` with three lines of one message (text with a null `stop_reason`, a line with `end_turn`, then a later line with a null `stop_reason`, each with its own `timestamp` and `gitBranch`). Assert that the text section's Message group has `stop_reason=end_turn` and the second line's `timestamp`, and that its Environment has the second line's `gitBranch`.
