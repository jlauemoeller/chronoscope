## Summary
The overlay behaves as specified: I traced every group through the code and ran the reader over eight real transcripts (3741 sections, all with a source, no `unavailable` group, every field location confirmed). ## Findings
1. [must-fix] Assembly is quadratic in a turn's text, thinking and injected items, which breaks the §5.2 requirement that the §9.2 "full parse under 2 s" budget still holds, and contradicts the build notes' "Assembly stays linear in a turn's items". `TurnSources::link` (`src/model/sources.rs:175`) runs `rposition` over the whole `items` table, and an item that is not linked yet is exactly the case that scans all of it. `link_message_item` (`src/harness/claude/assemble.rs:842`, `906`, `942`, `986`) and `link_line` (`:609`, `:635`, `:1195`) go through it for every new item. The `b.index` guards at those call sites only skip items that already exist, and commit 871b919 removed the scan for tool calls only (`add_call`). Measured in release with `Assembler::from_memory`, one Assistant turn, same machine (the branch figures for the last row vary with load):

   | one turn of | `main` | this branch |
   |---|---|---|
   | 25k text lines, 13 MB | 87 ms | 641 ms |
   | 50k text lines, 27 MB | 124 ms | 2 915 ms |
   | 100k text lines, 55 MB | 266 ms | 38 751 ms |
   | 200k text lines, 101 MB | 563 ms | 216 126 ms |
   | 50k rounds of text, tool call and result, 94 MB | 338 ms | 10 930-17 471 ms |

   `tests/budgets.rs` does not catch this because its fixtures have few items per turn (the dense one has 6 856 turns). It needs a long uninterrupted turn, so ordinary sessions are not affected. Change: give `TurnSources` a push-only method for an item the caller knows is new, as `add_call` does, and use it at all seven call sites. The `b.index` checks already establish this for the Assistant message items; the `(_, item)` arms and `HeldItem::link` hold a newly made `Injected` item. `get` can keep its `rfind`, which runs only when the overlay opens. I checked this direction in a scratch copy of HEAD by removing the scan from `link`: the figures return to `main`'s (101 MB of text 484 ms, 94 MB of rounds 305 ms). Add a long single-turn scenario that fails under the scanning code, for example a fixture in `tests/budgets.rs` of alternating text, tool call and result in one Assistant turn checked against the full-parse budget, so that this fails if it comes back. Correct the sentence in the build notes.

2. [must-fix] The references of three section kinds have no test. §5.3 gives a notice the Message group, the planner notes bind "the `model → …` note its message", and §5.3 gives system sections their source's Environment. I confirmed the gap by mutating a scratch copy of HEAD: with the `link_message_item` calls for `notice_id` (`assemble.rs:986`) and for `model:{msg_id}` (`:842`) removed, all 2832 tests pass; with the `link_line` in the flush arm (`:609`) and `held.link` in `on_assistant` removed, so that a system section in an Assistant turn has no source, all 2832 pass too. The code is correct today (checked with a probe on constructed transcripts, including all the setups in (c)), but nothing would fail if it broke. Change: in `tests/claude_details.rs` add (a) a message ending in `stop_reason: "max_tokens"`, where `notice:<id>` reads a Message group with that `stop_reason` and that line's Environment; (b) a second message with another model, where `model:<id>` reads the Environment of its message and no Message group; (c) a hook attachment in an Assistant turn, where `injected:<uuid>` reads the Environment of the first entry's line, in both setups that reach the untested lines: an attachment between two assistant lines of the same turn (the flush arm, `:609`), and held entries that open a new Assistant turn because the previous turn is a Compaction or there is none (`held.link` in `on_assistant`), for example boundary, summary, hook, assistant. A hook right after a prompt goes into the User turn, which `a_compaction_and_a_system_section_read_their_first_line_for_the_environment` already covers, and does not reach these lines.

3. [nit] `DetailsContent::label_width` (`src/components/details_overlay/content.rs:119`) counts the `unavailable` row, whose label is wider than `timestamp`. In a Prompt, compaction or User-turn system section with an unreadable source, the values sit two columns further right than the UI section's "no label column" implies. The build notes flag this, and a fix changes the accepted task-007 snapshot `unavailable_80x24_default`. This is layout, so I leave the call to the UI Reviewer. Change, if wanted: skip rows with an empty value and `muted` set in `label_width`.

4. [nit] A duplicate key in a line fails the derived heads, so the whole line shows `unavailable` (`src/harness/claude/details.rs`, `Line` and the nested heads). The build notes disclose it, and Claude Code's writer does not produce duplicates. Change: add a sentence to the `details.rs` module doc saying that a duplicated known key fails the line and shows `unavailable`.

5. [nit] `TurnSources::link_call` (`src/model/sources.rs:151`) is called only by its own unit test now that the assembler uses `add_call`. Change: remove it and move the test to `add_call`, or merge it into the method added for finding 1.

6. [nit] The comment at `tests/claude_details.rs:876` says the table "is small however big the line", but the assertion only checks that a reference exists. Change: assert that the turn's `Debug` output is small, or does not contain the 2 MB value, or drop the sentence.
