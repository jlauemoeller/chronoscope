## Summary
`a` on a subagent section resolves the session through `Harness::subagent()` and mounts a fresh `Transcript` at `Id::Subagent(depth)` over the parent, which stays mounted but is not drawn. The header carries one ` › Agent: <label>` segment per level and the subagent's id, and `Backspace` pops one level, drops its `WatchHandle` and refocuses the parent with its presentation unchanged. Every acceptance criterion has a test that would fail on wrong behaviour, and every required snapshot exists. I ran the gate myself: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `INSTA_UPDATE=no cargo test` all pass, with 1556 unit tests and all integration suites green. SPEC.md has no separate coding-guidelines section, and I found no breach of the architectural rules in §1.2/§1.3: the `App` owns the subagent stack and each transcript owns its own turns and presentation.

I weighed one deviation the builder disclosed. Covered transcripts keep receiving their own load's `Appended`, `Updated` and `Reset`. In `Transcript::change_turns` (`src/components/transcript/updates.rs`), an update can move the offset or the selection only through follow-at-bottom (§7.2: when following with the last section selected, the selection moves to the new end). It never touches folds, and it leaves a scrolled-up parent where it was. Dropping or buffering those batches would lose turns or give the same result later. So this agrees with §1.3's "returns to it unchanged" in the sense that counts: nothing the user does in the subagent changes the parent. The covered path still lacks a presentation test, see finding 1.

## Findings
1. [nit] No test covers the presentation of a parent that receives its own updates while covered. `a_covered_session_keeps_receiving_its_turns_and_the_header_stays_the_subagents` checks turn counts and warnings only. The realistic case is the parent's Task call getting its `tool_result` while the user reads the subagent. Change: in `src/app/browser_tests/subagent.rs`, add a test that scrolls the parent up, so it is not following, and records `presentation(&rig.app, Id::Transcript)`. It then opens depth 1, sends `ModelUpdate::Updated(..)` and `ModelUpdate::Appended(..)` on load 0 with `rig.harness.send(0, …)`, presses `Backspace`, and asserts that `selected`, `folds` and `offset` equal the recorded values.
2. [nit] A load number can be reused if mounting fails. In `App::open_subagent` (`src/app/browser.rs`), `self.browser.load_seq = generation;` runs only after `mount_subagent` succeeds. If the mount fails after `loader.load` has started a worker, the next subagent gets the same generation, and a batch already sent by the dropped worker would land in it. Change: move `self.browser.load_seq = generation;` to directly after `loader.load(..)` returns `Ok`.
3. [nit] A parent search still running when `a` is pressed is lost. `BrowserSearch` is per view, so its results arrive while the subagent's `search.pending` is on top and are dropped by `transcript_matches_arrived`. After `Backspace`, the parent's `search.pending` stays `Some(..)` and never resolves until the user searches again. Change: in `open_subagent`, clear the covered view's `search.pending` before pushing the level. Alternatively, route matches to the view whose `pending` equals `matches.generation()`, the same way `session_update` routes by generation.
4. [nit] The help line shows the same hints in a subagent view as at depth 0, with no mention of how to return. §4.2 asks for context-sensitive key hints. Change: optional. While `depth() > 0`, add a `Backspace to go back` hint, resolved through `keymap.label(Context::Browser, Action::Back)`.
5. [nit] At 80x24 the subagent's session id is left out of the right title (`the_subagent_80x24_text`). This follows the header's existing rule that names go first and the id goes when it cannot fit, since the 53-character id does not fit beside the breadcrumb in 80 columns. I record it so it is not read as an oversight; no change is needed unless the UI Reviewer wants a different truncation.
6. [nit] Covered transcripts get viewport pushes, but not any future theme or config attrs. Today nothing changes the theme at runtime, so this is not a bug. Task 031 (theme selector) must send theme changes to every `transcript_id(0..=depth)`, as `selector.rs` now does for `VIEWPORT_ATTR`, not just to `Id::Transcript`. Change: none now; mention it in the hand-off to 031.
